# 开发流程

一句话版：**改代码 → 双击 `rebuild-and-run.cmd`**。数据不会丢。

---

## 一、日常循环（99% 的情况）

```
1. 用编辑器打开   C:\Users\43720\Downloads\LightNote\smart_notes\
2. 改 lib\ 里的 .dart 文件
3. 保存
4. 双击           rebuild-and-run.cmd
5. 看到 App 窗口弹出来 = 成功
```

就这样。`rebuild-and-run.cmd` 干三件事：编译 → 启动 → **把数据库位置打印出来**。
失败会停在窗口里让你读错误（这是它和 `run.cmd` 的唯一区别）。

**建议**：右键 `rebuild-and-run.cmd` → 发送到 → 桌面快捷方式。以后双击桌面那个。

### 每次会看到这样的输出

```
数据库位置：
  C:\Users\43720\AppData\Roaming\com.example\smart_notes\LightNote\qing_notes.sqlite

  重新编译不会影响这个文件。
```

**这一行就是"我的数据在哪"的答案。** 如果它变成下面这样，说明有异常，要处理：

```
  ⚠️  注意：常规位置都不可写，数据临时落在程序目录里。
     这个位置在 build\ 下面，删 build\ 会连数据一起删。
```

### 编译要多久

| 改了什么 | 耗时 |
|---|---|
| 只改文案 / 界面 | 8–20 秒 |
| 改了多处逻辑 | 15–30 秒 |
| 加了新依赖 | 1–3 分钟（要下载） |
| `flutter clean` 之后第一次 | 约 50 秒 |

## 二、数据会不会丢

**不会。** 原因是数据根本不在工程目录里：

| 东西 | 在哪 | 重新编译会怎样 |
|---|---|---|
| **笔记数据库** | App 私有目录（`%APPDATA%\...\LightNote\`） | **完全不受影响** |
| 编译产物 | `build\` | 被覆盖 / 可随时删 |
| Dart 中间状态 | `.dart_tool\` | 被覆盖 / 可随时删 |
| 源码 | `lib\` `test\` `docs\` | 你不动它就不动 |

编译只碰 `build\` 和 `.dart_tool\`。数据库在 `%APPDATA%` 里，两者毫不相干。

**唯一例外**：如果上面那行输出了「数据临时落在程序目录里」的红色警告，
说明常规位置都写不进去、数据退到了 `build\` 下面——
那种情况下**删 `build\` 就会连数据一起删**。这时第一件事是去
「设置 → 存储位置 → 更换工作目录」把它搬到安全的地方。

### 这些操作都**不会**丢数据

- 改代码、重新编译
- `flutter clean`
- 删 `build\` 目录
- 删 `.dart_tool\` 目录
- 关掉 App 再打开
- 电脑重启

### 这些操作**会**丢数据

| 操作 | 后果 | 怎么避免 |
|---|---|---|
| 删 App 私有目录 `%APPDATA%\com.example\smart_notes\` | 笔记全没 | 先导出备份包 |
| 卸载 / 重装 App（Android 上卸载会清私有目录） | 笔记全没 | 先导出备份包 |
| 手工改 `qing_notes.sqlite` | 库损坏 | 别用别的工具去写它 |
| 删掉工作目录里的 `qing_notes.sqlite` | 笔记全没 | 同上 |

### 保险做法：定期导出备份

「设置 → 导出备份包（.zip）」→ 选个位置（比如 D 盘或网盘同步目录）。
那是个标准 zip，里面就是完整数据库。换电脑、换手机、重装系统都能恢复。

顺便自动留档：导出时 App 会**额外**在私有目录的 `backups\` 里留一份。

## 三、什么时候需要多做一步

### 情况 1：改了数据库表结构

改了 `lib\core\db\tables.dart`（加表、加字段、改字段）之后：

```powershell
cd C:\Users\43720\Downloads\LightNote\smart_notes
dart run build_runner build
```

然后再双击 `rebuild-and-run.cmd`。

**注意**：不跑 `build_runner` 的话编译会报 `app_database.g.dart` 相关的错。

改了表结构之后，**老数据库缺新字段**。开发阶段最省事的做法是让 App 重建库：

1. 先把现有笔记导出备份（设置 → 导出备份包）
2. 删掉 `qing_notes.sqlite`（位置看每次启动打印的那行，或设置页）
3. 重新打开 App，会建一个带新结构的空库 + 种子数据
4. 需要老数据就「从备份包导入」

> 正式发布之后就不能这么干了，必须写迁移（见 `app_database.dart` 里
> `MigrationStrategy` 的注释）。现在还在开发期，删库重建最快。

### 情况 2：加了新依赖

改 `pubspec.yaml` 之后：

```powershell
.\tool\run.cmd pubget
```

然后正常编译。第一次会因为下载依赖慢一点（1–3 分钟）。

### 情况 3：想跑测试 / 看静态分析

```powershell
.\tool\run.cmd test        # 75 个测试，约 5 秒
.\tool\run.cmd analyze     # 静态分析
.\tool\verify_all.cmd      # 一次跑完 analyze + test + build + 启动 App 并检查数据库
```

> ⚠️ `flutter analyze` 对刚保存的改动**有缓存延迟**，偶尔会说
> "No issues found" 而实际编译报错。**以 `build` 的结果为准。**

## 四、出问题了怎么办

### 「打不开本地数据库」

App 会显示一个诊断页，上面列了每个候选位置各自的失败原因。
**首先那不是数据丢了**——原来的文件还在磁盘上，只是这次没访问到。

临时办法：设一个环境变量指定位置，然后重新打开 App。

```powershell
setx QING_NOTES_DB_DIR "D:\我的笔记数据"
```

重开终端后生效。想撤销：`setx QING_NOTES_DB_DIR ""`。

### App 里笔记看起来「没了」

先看每次启动打印的那行「数据库位置」。如果它显示的位置和你以为的不一样，
说明 App 换了位置去找库（降级了）。按上一节的办法固定位置。

### 编译报 `Unable to find suitable Visual Studio toolchain`

VS 的安装位置记录失效了（搬动 `tools\` 目录会导致）。
`run.cmd` 会在构建前自动修（`tool\fix_vs_toolchain.ps1`）。
如果自动修也失败，看该脚本头部的说明。

### 编译报 `Building with plugins requires symlink support`

同样由 `run.cmd` 自动处理（`tool\fix_plugin_symlinks.ps1`）。
**如果你绕过 `run.cmd` 直接敲 `flutter build`**，就会遇到这个。

### 报 `CMakeCache.txt directory ... is different`

`build\` 里的 CMake 缓存写死了旧的源码路径（工程搬过家）。
删掉重来：

```powershell
Remove-Item -Recurse -Force build\windows
.\tool\run.cmd
```

### 报 `PathAccessException` / 卡在 `Running pub upgrade...`

直接敲 `flutter` 的后果——本机 `dart.exe` 写不了真实 AppData。
**用 `run.cmd`，不要直接敲 `flutter`。**

### 上传前想确认一切正常

```powershell
.\tool\verify_all.cmd
```

会依次跑 analyze → test → build → 启动 App 并检查数据库建出来了没有。
全绿就可以放心。

## 五、不要做的事

| ❌ 别做 | ✅ 改成 |
|---|---|
| 直接敲 `flutter build` / `flutter run` | `.\tool\run.cmd` |
| 用 `.ps1`（`.\tool\run.ps1`） | 用 `.cmd`（执行策略会拦 `.ps1`，且环境变量会丢） |
| 手工改 `build\` 里的东西 | 那些是生成物，改了下次编译就被覆盖 |
| 单独移动 `smart_notes\` 到别处 | `tools\` 必须和它同级；要搬就整个 `LightNote\` 一起搬 |
| 删 `Downloads\py\tools\vsbuildtools` | 那是 VS 工具链的目录联接，删了编译就找不到编译器 |
| 用别的工具（DB Browser 等）**写** `qing_notes.sqlite` | 可以只读查看；要改数据请用 App 或导入备份包 |

## 六、完整命令速查

```powershell
cd C:\Users\43720\Downloads\LightNote\smart_notes

# 日常
.\rebuild-and-run.cmd              # 编译 + 启动（失败会停住显示错误）
.\tool\run.cmd                     # 同上，不停留

# 分开做
.\tool\run.cmd build               # 只编译 debug
.\tool\run.cmd release             # 编译 release（整个目录可拷走单独运行）
.\tool\run.cmd test                # 跑测试
.\tool\run.cmd analyze             # 静态分析
.\tool\run.cmd pubget              # 拉依赖
.\tool\run.cmd doctor              # 环境自检
.\tool\run.cmd flutterrun          # 需要热重载时（注意：数据库位置会不一样）
.\tool\run.cmd raw pub get -v      # 透传任意 flutter 命令

# 深度排查
.\tool\diag.cmd                    # 工具链 / 符号链接 / 生成代码 / 产物
.\tool\verify_all.cmd              # analyze + test + build + 启动验证
.\tool\inspect_db.cmd              # 直接看数据库内容（表/索引/行数）
.\tool\inspect_db.cmd <文件路径>    # 看指定文件

# 改了表结构之后
dart run build_runner build
```

更细的脚本说明见 [tool/README.md](../tool/README.md)。
