## 1. 第一个要义是轻

> 软件的第一个要义是轻

### 1.1 「使用轻的技术栈」

> 使用轻的技术栈,功能上做减法

**在代码里的落点**

- 运行时直接依赖 **14 个第三方包**（`pubspec.yaml`）：`drift` / `sqlite3` / `path_provider` / `path` /
  `uuid` / `provider` / `dio` / `flutter_secure_storage` / `gpt_markdown` / `cupertino_icons` /
  `archive` / `file_selector` / `crypto` / `share_plus`。dev 依赖 6 个，其中 `path_provider_platform_interface` /
  `plugin_platform_interface` 本来只是传递依赖，显式列出只为满足 `depend_on_referenced_packages`。
- `pubspec.lock` 里总共 **127 个包**（含 Flutter SDK 自带与全部传递依赖）。
- **只有一套代码生成器**：`drift_dev` + `build_runner`。`lib/core/db/tables.dart` 是全项目唯一
  需要跑 `build_runner` 的文件。
- 刻意拒绝的依赖——**逐条在 `pubspec.lock` 里查证过确实不存在**（不是"没写进 `pubspec.yaml`"）：

| 被拒绝的包                                 | 本项目用什么替代                                                                                |
| ------------------------------------- | --------------------------------------------------------------------------------------- |
| `shared_preferences`                  | 数据库里的 `app_kv` 表（`PreferencesService`）；偏好随笔记进同一个备份包                                     |
| `riverpod` / `riverpod_generator`     | `provider`（**只做依赖注入**）+ drift 的 `watch()` / `StreamBuilder`（全项目**没有** `ChangeNotifier`） |
| `freezed` / `json_serializable`       | 模型与 JSON 全手写，不引入第二套生成器                                                                  |
| `sqflite` / `sqlite3_flutter_libs`    | drift ≥ 2.32 起由 `sqlite3` 的 build hooks 自动打包原生库                                         |
| `hive` / `get_it` / `bloc`            | 不需要第二套存储或依赖注入                                                                           |
| `file_picker`                         | Flutter 官方的 `file_selector`（Windows 走 IFileDialog、Android 走 SAF，且不需要存储权限）               |
| `url_launcher` / `permission_handler` | 用不到（`share_plus` **不再是**这一类：Android 导出备份包要走系统分享面板，见《架构和功能开发流程设计》）                       |

- 选型理由与**代价（放弃了什么）不在这里重复**，见 [技术栈设计](技术栈设计.md)。

## 2. 「笔记库平铺而不是模仿文件系统」

> 笔记库平铺而不是模仿文件系统

**在代码里的落点**

- `lib/core/db/tables.dart` 的 `Notebooks` 表全部字段只有：
  `id` / `name` / `sortOrder` / `createdAt` / `updatedAt` / `deletedAt`。
  **没有 `parentId`，也没有任何自引用外键**——表结构层面就不可能嵌套。
- `sortOrder` 的注释已经把口径改掉：`用于列表展示排序。**不再是"同层内"排序**——没有层了。`
  （`tables.dart`）
- 层级是被**迁移主动删掉**的，不是"从没写过"：v2→v3 执行
  `ALTER TABLE notebooks DROP COLUMN parent_id`，并 `DROP INDEX IF EXISTS idx_folders_parent`；
  SQLite < 3.35 的退路是把 `parent_id` 全部置 NULL（[数据库设计](数据库设计.md)）。
- 改名与去层级是同一次动作：`folders` → `notebooks`、`folder_id` → `notebook_id`、
  `workspace_folder_id` → `workspace_notebook_id`。文件头写明：
  **全项目没有任何 `folder_*` 列，也没有任何 `@JsonKey` 列名映射**（`tables.dart`）。
- 理由就写在表定义里（`tables.dart`）：当初采用 SQLite 而非文件系统，本来就是为了
  不模仿目录树；再长出子目录等于把文件系统的复杂性又搬回来。
- 界面对齐：笔记库页没有层级展示，**刻意没有「新建子笔记库」**（[界面设计](界面设计.md)）。
- 顺带把层级最容易出错的边界也一并去掉了：删笔记库不再需要"子目录上浮"
  （[界面设计](界面设计.md)），改成**不删笔记**——一个事务里把库内笔记
  `notebook_id → NULL` 且 `is_inbox → true`（回到「我的轻笔记」），再逻辑删除笔记库本身
  （[数据库设计](数据库设计.md)）。直接级联删笔记会是数据丢失事故。
- **两处容易看成"层级还在"，其实都不是**：
  - 切片的 `note_chunks.heading` 存 `工作 / 项目A / 风险` 这种**标题路径**（`tables.dart`）——
    它描述的是"这一片落在**这一篇笔记的**哪个 Markdown 标题下"，与笔记库的平铺无关；
  - v2→v3 迁移里仍会出现 `folders` 这个名字，备份校验也同时接受新旧两个表名
    （`tables.dart`）——那是给老库 / 老备份准备的兼容层，不是残留的层级字段。

## 3. 「笔记的大小有限制,各个字段的上限有限制」

> 笔记的大小有限制,各个字段的上限有限制

**在代码里的落点**

上限数值集中在一个文件：`lib/core/util/ai_limits.dart`。它的写法本身就是落点——文件头写明
「**对 AI 消费的内容要狠，对用户生产的内容要软**」，并要求所有数值集中在此，
避免"prompt 里写 300、代码里截 500"。

| 对象                   | 上限                                                                       | 超限会发生什么                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 笔记正文                 | 软 80 KB（`ai_limits.dart`）                                                | **只提示**：横幅「笔记较长（x KB）」+「继续变长可能影响编辑流畅度」                                                                                                                      |
| 笔记正文                 | 强警告 90 KB（`ai_limits.dart`）                                              | **只提示**：「笔记偏长（x KB）」+「建议拆成多篇。还能继续编辑，超过 100 KB 就无法保存了」                                                                                                       |
| 笔记正文                 | 硬 100 KB（`ai_limits.dart`）                                               | **拒绝保存**：`_flush()` 直接 return、保存状态显示为失败，内容仍留在编辑器里（`note_editor_page.dart`）；横幅给「裁剪到 80 KB」按钮，先弹确认「**这个操作不能撤销**」（`note_editor_page.dart`）。**这一档绝不静默截断用户写的东西** |
| 笔记标题                 | 200 字（`ai_limits.dart`）                                                  | **截断**：落盘前 `safeTruncate`。理由是标题会进 prompt，一个几万字的"标题"能直接把一次请求撑爆（`note_editor_page.dart`）                                                                      |
| AI 摘要                | 目标 150–250 字（`ai_limits.dart`）                                           | 提示词里要求                                                                                                                                                      |
| AI 摘要                | 硬 300 字（`ai_limits.dart`）                                                | **强制截断**。注释里给了实测证据：要求 60 字模型会返回 160 字，**不能只靠提示词**                                                                                                           |
| 卡片标签                 | **一个**（`ai_limits.dart` 的 `sanitizeTag`）                                 | 卡片**只生成一个标签**；"生成 2~6 个"的旧设计与 `tagCountMin` / `tagCountMax` 两个常量都已删除。"宁可存少，也不要为了凑数"这条理由仍然成立，只是现在连"凑数"的机会都没有了                                                |
| 卡片标题 / 正文            | 60 字 / 2000 字（`ai_limits.dart` 的 `feedCardTitleMax` / `feedCardBodyMax`） | 在 `AiPrompts.parseFeedCards` 里**截断**。提示词只要"标题 ≤30 字、正文 400–800 字"，这里给两倍余量兜底 —— 模型偶尔会跑飞（实测有返回几千字的），而卡片正文会被收进笔记、也会进 prompt。**模型的自我约束不算约束**（`prompts.dart`）    |
| 单个标签                 | ≤5 个汉字 / ≤12 个英文字母（`ai_limits.dart`）                                     | 按配额逐字符截断，并剥掉 `#`、引号、`「」『』【】` 这类包装字符（`ai_limits.dart`）                                                                                                       |
| 列表预览 `notes.excerpt` | 前 200 字（[数据库设计](数据库设计.md)）                                               | 截断后加 `…`；目的是列表页不读全文                                                                                                                                         |
| 切片 `note_chunks`     | 片 700 字 / 不可拆散单元硬顶 1500 字（`note_chunker.dart`）                           | 前者切，后者硬顶。1500 的来源是 `readChunk` 的单次预算：一片超过 1500，AI 根本读不进来，作为"片"就没意义                                                                                          |
| 搜索历史                 | 20 条（`preferences_service.dart`）                                         | 超量删除                                                                                                                                                        |
| AI 聊天历史              | 单条 500 字 / 只带最近 5 轮（`ai_chat_repository.dart`）                           | 截断处显式标「…（已截断）」                                                                                                                                              |
| 进 prompt 的单条笔记正文     | AI 助手 6000 字（`ai_chat_repository.dart`）                                  | 截断                                                                                                                                                          |
| 进 prompt 的**摘要**输入正文 | 2 万字（`prompts.dart` 的 `summaryInputMaxChars`）                            | 截断并在提示里显式注明"已被截断"。按**成本**定：摘要是 ≤300 字的概括，2 万字足够（早先这个常量是 20 万字、比笔记硬上限还大，**永远触发不了**，等于没有上限）                                                                   |
| 笔记者名类短字段             | 200 字（`ai_limits.dart` 的 `titleHardMax`，与标题同一个常量）                        | **截断**：笔记本名收口在 `NotebookRepository._cleanName`，界面与 AI 的 `createNotebook` / `renameNotebook` 都走它                                                             |
| AI 确认弹层里"改前 / 改后"    | 600 字（`agent_dialogs.dart`）                                              | 截断并标注                                                                                                                                                       |

**上限不只在界面那一层 —— 每条写入路径都要过：**

- **AI 的工具写入走同一套上限**（`ToolExecutor._fitForSave()`）：`createNote` / `updateNote` /
  `appendToNote` 一律先过"标题截断 + 正文到硬上限失败"，而且**拦在确认层之前**
  （不让用户去确认一件注定写不进去的事）。失败原因写给模型看（"请拆成多篇"），
  工具描述里也写了这两个数。**只拦界面等于没拦** —— 同一张表有两条写入路径。
- **派生字段只有一处实现**：`excerpt`（剥 Markdown 后截 200 字）与 `wordCount`
  （先剥 Markdown，再"中文按字 + 英文按词"）都在 `core/util/text_utils.dart`，
  编辑页与 AI 两条写入路径都调它。抄一份私有的，代价就是同一篇笔记
  "AI 写过"和"人改过"在列表里显示的字数不一样。

两处判据用**字节**而不是字符，理由写在代码里（`ai_limits.dart`、
`note_editor_page.dart`）：中文一个字 3 字节，按字符算会**低估三倍**，而数据库与 token
成本都跟字节数更相关。分档边界是**闭区间下界**（正好 80 KB 算"较长"、正好 100 KB 就拒绝保存），
免得出现"显示 100.0 KB 却还能保存"的矛盾（`ai_limits.dart`）。

## 4. 「不做语音输入」

> 不做语言输入的功能,因为这不是一款轻笔记想要的,这是输入法做的事情

（原话里的"语言输入"就是下文代码与文档一致称呼的**语音输入**；原话逐字保留，不改写。）

**在代码里的落点**

- `pubspec.yaml` 与 `pubspec.lock` 里**没有任何语音或音频相关包**：`speech_to_text`、`record`、
  `flutter_sound`、`just_audio`、`audio_session` 等全部不存在（在 127 个锁定包里逐条查过）。
  注意 `record_use` 是 Dart SDK 的构建工具包，与录音无关。
- `lib/` 下 68 个 dart 文件里，`speech` / `voice` / `audio` / `SpeechToText` / `microphone`
  **零命中**。
- 输入只有一条路：`note_editor_page.dart` 的原生 `TextField` + Markdown 文本，输入的事交给系统
  输入法。[界面设计](界面设计.md) 的 14 个页面清单里也没有任何录音入口。
- 用户的理由（"这是输入法做的事情"）与代码的实际分工一致：**文字输入与语音识别都是系统输入法的
  职责，本项目不重复实现**。
- **权限清单与这条原则对齐**：`AndroidManifest.xml`（main / debug / profile 三份）里
  **只有 `INTERNET`**，没有任何麦克风、相机、相册、外部存储权限 —— 曾经由模板带进来的
  `RECORD_AUDIO` / `CAMERA` / `READ_MEDIA_IMAGES` / `READ_EXTERNAL_STORAGE` 已经删掉。
  要加相机 / 相册 / 录音时**再加回来**；在那之前它们只会在系统权限页上让用户困惑。
  （同类原则见 [界面设计](界面设计.md) 的「明确不做」一节：图片也不支持插入。）

## 5. 「第二要义得省钱,想办法节省token使用」

> 第二要义得省钱,想办法节省token使用

**费用模型与完整的省钱机制不在这里展开，见 [AI接入设计](AI接入设计.md) 的「费用模型与省钱策略」一节。**
本节只记录：这条原则**约束了哪些设计决策**（每条一句话，细节去那份文档）。

| 由此产生的设计决定                                     | 一句话                                                                                                             | 落点                                                                                                       |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 切片只存偏移、不存正文                                   | 库里只留一份可喂给 AI 的正文，切片不复制文本，也就不存在"片正文过期"                                                                           | `tables.dart`、[数据库设计](数据库设计.md) 第 9 节                                                                    |
