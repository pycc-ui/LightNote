# 软件理念设计

这个软件有两条要义：**轻**、**省钱（省 token）**。下面每一条先给出要义原话，再说它具体约束了什么。
细节分散在各自的文档里：选型理由见 [技术栈设计](技术栈设计.md)，表结构见 [数据库设计](数据库设计.md)，
页面见 [界面设计](界面设计.md)，费用机制见 [AI接入设计](AI接入设计.md)，文件放哪见 [目录设计](目录设计.md)。

## 1. 第一个要义是轻

> 软件的第一个要义是轻

### 1.1 用轻的技术栈，功能上做减法

> 使用轻的技术栈,功能上做减法

运行时直接依赖 **14 个第三方包**（`pubspec.yaml`）：`drift` / `sqlite3` / `path_provider` / `path` /
`uuid` / `provider` / `dio` / `flutter_secure_storage` / `gpt_markdown` / `cupertino_icons` /
`archive` / `file_selector` / `crypto` / `share_plus`。dev 依赖 6 个，其中 `path_provider_platform_interface` /
`plugin_platform_interface` 本是传递依赖，显式列出只为满足 `depend_on_referenced_packages`。
`pubspec.lock` 一共 **127 个包**（含 Flutter SDK 自带与全部传递依赖）。全项目只有一套代码生成器
（`drift_dev` + `build_runner`），`lib/core/db/tables.dart` 是唯一需要跑 `build_runner` 的文件。

下面这些包被**刻意拒绝**，`pubspec.lock` 里确实不存在（不是"没写进 `pubspec.yaml`"）：

| 被拒绝的包 | 用什么替代 |
| --- | --- |
| `shared_preferences` | 数据库里的 `app_kv` 表（`PreferencesService`）；偏好随笔记进同一个备份包 |
| `riverpod` / `riverpod_generator` | `provider`（只做依赖注入）+ drift 的 `watch()` / `StreamBuilder`（全项目没有 `ChangeNotifier`） |
| `freezed` / `json_serializable` | 模型与 JSON 全手写，不引入第二套生成器 |
| `sqflite` / `sqlite3_flutter_libs` | drift ≥ 2.32 起由 `sqlite3` 的 build hooks 自动打包原生库 |
| `hive` / `get_it` / `bloc` | 不需要第二套存储或依赖注入 |
| `file_picker` | Flutter 官方的 `file_selector`（Windows 走 IFileDialog、Android 走 SAF，且不需要存储权限） |
| `url_launcher` / `permission_handler` | 用不到 |

### 1.2 功能上做减法

这个 App 主动删掉了不少功能。数据库层面删掉的表如下，建表语句只剩在
`test/migration_test.dart` 里（否则 `DROP TABLE` 是空转，"删掉了"的断言没有意义）：

| 删掉的表 | 版本 | 对应被删掉的功能 |
| --- | --- | --- |
| `cards` / `card_decks` / `reviews` | v6 | 记忆卡片（SM-2 间隔复习）整体移除，由「轻笔记」AI 卡片流取代 |
| `note_summaries` | v7 | 编辑页 `✨`「AI 整理要点」的落库表（只写不读），功能入口一并移除 |
| `note_feed_state` | v8 | 卡片流"复习已有笔记"时代的调度状态（due / interval / ease / starred） |
| `note_ai_tags` | v8 | 每篇笔记的 AI 标签（读侧链路零调用方） |
| `tags` / `note_tags` | v9 | 用户手动打的笔记标签 |

字段层面：`notes.reading_progress` / `reading_seconds` 已移除——沉浸阅读页下线后它们没有写入方，
留着只会误导（[数据库设计](数据库设计.md)）。

功能与界面层面：

| 被删掉的东西 | 现状 | 出处 |
| --- | --- | --- |
| 沉浸阅读模式 | 整体移除 | [界面设计](界面设计.md) |
| Markdown 导出 | `MarkdownExportService`（含 `renderSingle` / `exportAll`）全部移除，编辑页菜单不再有这一项；只留「复制全文」（纯文本，`TextUtils.noteCopyText`） | [数据库设计](数据库设计.md) |
| 图片插入 / 远程图片渲染 | 不支持插图。正文里的 `![alt](url)` 不加载图片，只把 alt 与 URL 当文本显示——渲染即向第三方服务器发请求 | [界面设计](界面设计.md) |
| 编辑器「自动保存」开关 | 移除。保存方式定案为手动，留个开关只会让人以为还能自动保存 | [界面设计](界面设计.md) |
| 设置 · AI 的模型选择器 | 移除。`deepseek_config.dart` 里注释说明曾有 `modelPro` 与一张模型选择表 | [界面设计](界面设计.md) |
| 设置 · AI「深度整理时启用思考模式」开关 | 移除。思考强度改在 AI 页顶部按会话选 | [界面设计](界面设计.md) |
| 「AI 数据使用授权」开关 | 移除 | [界面设计](界面设计.md) |
| 首次进 AI 页的隐私授权横幅与发送闸门 | 整体移除——不把隐私做成一个需要用户操作的功能，只留说明文字 | [界面设计](界面设计.md) |
| 卡片预览文案（摘要 / 预览 50–100 字 / 固定屏高） | 常量还在，卡片已不用。卡片上只剩标题（≤3 行）+ 一个标签 chip + 「点开看全文」 | [界面设计](界面设计.md) |
| 上拉加载 / 滚到底自动加载 | 没有。滚到底什么都不做 | [界面设计](界面设计.md) |
| 「新建子笔记库」 | 刻意没有 | [界面设计](界面设计.md) |
| AI 进底部导航 | 没有。它是"偶尔进去问一次"的助手，不与三个主页面平级占常驻 tab | [界面设计](界面设计.md) |
| 回收站 | 没有入口。逻辑删除字段与 `AppDatabase.restoreNote()` 都在（`app_database.dart`、`note_repository.dart`），但只服务左滑删除的 3 秒撤销；工具描述里直接写「不可恢复——App 没有回收站」 | `tool_executor.dart`、`tool_specs.dart` |
| 卡片流翻卡自动调 AI | 刻意没有：翻卡片不烧 token | [界面设计](界面设计.md) |
| 多设备同步 | 未实现。UUID 主键与 `deletedAt` 只是为将来同步预留 | [数据库设计](数据库设计.md) |

## 2. 笔记库平铺，不模仿文件系统

> 笔记库平铺而不是模仿文件系统

`lib/core/db/tables.dart` 的 `Notebooks` 表全部字段只有：
`id` / `name` / `sortOrder` / `createdAt` / `updatedAt` / `deletedAt`。
没有 `parentId`，也没有任何自引用外键——表结构层面就不可能嵌套。
`sortOrder` 的注释写明它用于列表展示排序，因为没有层级，所以不是「同层内」排序。

层级是被迁移**主动删掉**的，不是从没写过：v2→v3 执行
`ALTER TABLE notebooks DROP COLUMN parent_id`，并 `DROP INDEX IF EXISTS idx_folders_parent`；
SQLite < 3.35 的退路是把 `parent_id` 全部置 NULL（[数据库设计](数据库设计.md)）。

改名与去层级是同一次动作：`folders` → `notebooks`、`folder_id` → `notebook_id`、
`workspace_folder_id` → `workspace_notebook_id`。所以现在全项目没有任何 `folder_*` 列，
也没有任何 `@JsonKey` 列名映射。当初采用 SQLite 而非文件系统，本来就是为了不模仿目录树；
再长出子目录等于把文件系统的复杂性又搬回来。

界面对齐：笔记库页没有层级展示，刻意没有「新建子笔记库」（[界面设计](界面设计.md)）。
删笔记库也不再需要"子目录上浮"，改成**不删笔记**——一个事务里把库内笔记
`notebook_id → NULL` 且 `is_inbox → true`（回到「我的轻笔记」），再逻辑删除笔记库本身
（[数据库设计](数据库设计.md)）。直接级联删笔记会是数据丢失事故。

两处容易看成"层级还在"，其实都不是：切片的 `note_chunks.heading` 存 `工作 / 项目A / 风险`
这种**标题路径**（`tables.dart`），它描述的是"这一片落在这一篇笔记的哪个 Markdown 标题下"，
与笔记库的平铺无关；v2→v3 迁移里仍会出现 `folders` 这个名字、备份校验也同时接受新旧两个表名
（`tables.dart`），那是给老库 / 老备份准备的兼容层，不是残留的层级字段。

## 3. 对笔记大小和各字段上限做限制

> 笔记的大小有限制,各个字段的上限有限制

上限数值集中在 `lib/core/util/ai_limits.dart`。它的原则是**对 AI 消费的内容要狠，对用户生产的内容要软**，
并要求所有数值集中在此，避免"prompt 里写 300、代码里截 500"。

| 对象 | 上限 | 超限会发生什么 |
| --- | --- | --- |
| 笔记正文 | 软 80 KB（`ai_limits.dart`） | 只提示：横幅「笔记较长（x KB）」+「继续变长可能影响编辑流畅度」 |
| 笔记正文 | 强警告 90 KB（`ai_limits.dart`） | 只提示：「笔记偏长（x KB）」+「建议拆成多篇。还能继续编辑，超过 100 KB 就无法保存了」 |
| 笔记正文 | 硬 100 KB（`ai_limits.dart`） | 拒绝保存：`_flush()` 直接 return、保存状态显示为失败，内容仍留在编辑器里（`note_editor_page.dart`）；横幅给「裁剪到 80 KB」按钮，先弹确认「这个操作不能撤销」（`note_editor_page.dart`）。这一档绝不静默截断用户写的东西 |
| 笔记标题 | 200 字（`ai_limits.dart`） | 截断：落盘前 `safeTruncate`。理由是标题会进 prompt，一个几万字的"标题"能直接把一次请求撑爆（`note_editor_page.dart`） |
| AI 摘要 | 目标 120–200 字（`ai_limits.dart`） | 提示词里要求 |
| AI 摘要 | 硬 220 字（`ai_limits.dart`） | 强制截断。要求 60 字模型会返回 160 字，不能只靠提示词 |
| 卡片标签 | 一个（`ai_limits.dart` 的 `sanitizeTag`） | 卡片只生成一个标签；"生成 2~6 个"的旧设计与 `tagCountMin` / `tagCountMax` 两个常量都已删除 |
| 卡片标题 / 正文 | 60 字 / 2000 字（`ai_limits.dart` 的 `feedCardTitleMax` / `feedCardBodyMax`） | 在 `AiPrompts.parseFeedCards` 里截断。提示词只要"标题 ≤30 字、正文 400–800 字"，这里给两倍余量兜底——模型偶尔会跑飞（实测有返回几千字的），而卡片正文会被收进笔记、也会进 prompt。模型的自我约束不算约束（`prompts.dart`） |
| 单个标签 | ≤5 个汉字 / ≤12 个英文字母（`ai_limits.dart`） | 按配额逐字符截断，并剥掉 `#`、引号、`「」『』【】` 这类包装字符（`ai_limits.dart`） |
| 列表预览 `notes.excerpt` | 前 200 字（[数据库设计](数据库设计.md)） | 截断后加 `…`；目的是列表页不读全文 |
| 切片 `note_chunks` | 片 700 字 / 不可拆散单元硬顶 1500 字（`note_chunker.dart`） | 前者切，后者硬顶。1500 的来源是 `readChunk` 的单次预算：一片超过 1500，AI 根本读不进来，作为"片"就没意义 |
| 搜索历史 | 20 条（`preferences_service.dart`） | 超量删除 |
| AI 聊天历史 | 单条 500 字 / 只带最近 5 轮（`ai_chat_repository.dart`） | 截断处显式标「…（已截断）」 |
| 进 prompt 的单条笔记正文 | AI 助手 6000 字（`ai_chat_repository.dart`） | 截断 |
| 进 prompt 的摘要输入正文 | 2 万字（`prompts.dart` 的 `summaryInputMaxChars`） | 截断并在提示里显式注明"已被截断"。按成本定：摘要是 ≤220 字的概括，2 万字足够 |
| 笔记者名类短字段 | 200 字（`ai_limits.dart` 的 `titleHardMax`，与标题同一个常量） | 截断：笔记本名收口在 `NotebookRepository._cleanName`，界面与 AI 的 `createNotebook` / `renameNotebook` 都走它 |
| AI 确认弹层里"改前 / 改后" | 600 字（`agent_dialogs.dart`） | 截断并标注 |

上限不只在界面那一层，每条写入路径都要过：

- AI 的工具写入走同一套上限（`ToolExecutor._fitForSave()`）：`createNote` / `updateNote` /
  `appendToNote` 一律先过"标题截断 + 正文到硬上限失败"，而且拦在确认层之前
  （不让用户去确认一件注定写不进去的事）。失败原因写给模型看（"请拆成多篇"），
  工具描述里也写了这两个数。只拦界面等于没拦——同一张表有两条写入路径。
- 派生字段只有一处实现：`excerpt`（剥 Markdown 后截 200 字）与 `wordCount`
  （先剥 Markdown，再"中文按字 + 英文按词"）都在 `core/util/text_utils.dart`，
  编辑页与 AI 两条写入路径都调它。抄一份私有的，代价就是同一篇笔记
  "AI 写过"和"人改过"在列表里显示的字数不一样。

两处判据用**字节**而不是字符，理由见 `ai_limits.dart`、`note_editor_page.dart`：中文一个字 3 字节，
按字符算会低估三倍，而数据库与 token 成本都跟字节数更相关。分档边界是**闭区间下界**
（正好 80 KB 算"较长"、正好 100 KB 就拒绝保存），免得出现"显示 100.0 KB 却还能保存"的矛盾
（`ai_limits.dart`）。

## 4. 不做语音输入

> 不做语言输入的功能,因为这不是一款轻笔记想要的,这是输入法做的事情

（原话里的"语言输入"即下文代码与文档一致称呼的**语音输入**。）

`pubspec.yaml` 与 `pubspec.lock` 里没有任何语音或音频相关包：`speech_to_text`、`record`、
`flutter_sound`、`just_audio`、`audio_session` 等都不存在。注意 `record_use` 是 Dart SDK 的构建工具包，
与录音无关。`lib/` 下 68 个 dart 文件里，`speech` / `voice` / `audio` / `SpeechToText` / `microphone`
零命中。

输入只有一条路：`note_editor_page.dart` 的原生 `TextField` + Markdown 文本，输入的事交给系统输入法。
[界面设计](界面设计.md) 的 15 个页面清单里也没有任何录音入口。文字输入与语音识别都是系统输入法的职责，
本项目不重复实现。

权限清单与这条原则对齐：`AndroidManifest.xml`（main / debug / profile 三份）里只有 `INTERNET`，
没有任何麦克风、相机、相册、外部存储权限——曾经由模板带进来的
`RECORD_AUDIO` / `CAMERA` / `READ_MEDIA_IMAGES` / `READ_EXTERNAL_STORAGE` 已经删掉。
要加相机 / 相册 / 录音时再加回来；在那之前它们只会在系统权限页上让用户困惑。
（图片也不支持插入，见 [界面设计](界面设计.md) 的「明确不做」。）

## 5. 第二要义：省 token

> 第二要义得省钱,想办法节省token使用

费用模型与完整的省钱机制见 [AI接入设计](AI接入设计.md) 的「费用模型与省钱策略」。
这里只记这条原则约束了哪些设计决策：

| 设计决定 | 理由 | 落点 |
| --- | --- | --- |
| 切片只存偏移、不存正文 | 库里只留一份可喂给 AI 的正文，切片不复制文本，也就不存在"片正文过期" | `tables.dart`、[数据库设计](数据库设计.md) |
| 会话历史只带最近 5 轮 | 历史每轮都要重发，钉死上限把总成本从 `O(N²)` 拉回 `O(N)` | `ai_chat_repository.dart` |
| 更早的历史压成一段摘要，且只生成一次 | 之后每轮直接读，不再每轮重复支付"压缩"那次调用 | `ai_chat_repository.dart`（`ai_history_summary_<会话id>`，存 `app_kv`） |
| 工具分层下发（22 个 = 核心 7 / 常用 10 / 按需 5） | 核心层带完整 schema、常用层省掉 schema、按需层只在目录里给一行 | `tool_specs.dart`、[AI接入设计](AI接入设计.md) |
| 读笔记按需：目录先行、正文按片取 | `listNotes` 只取 id / 标题 / 所属库 / 修改时间（`noteBriefs`）；`getNoteMeta` 与 `listChunks` 不含正文；`readChunk` 每轮 ≤3 片 ≤1500 字 | `tool_executor.dart` |
| 默认 `deepseek-flash`，`modelPro` 与模型选择表一并删掉 | 少一个"改了没反应的开关"，也少一条通向 3–4 倍价格的路 | `deepseek_config.dart`、[AI接入设计](AI接入设计.md) |
| 每个入口显式 `thinking: disabled` | 官方默认开思考且 effort 默认 high，不管它连"加个标签"都走完整推理链 | `deepseek_client.dart` |
| 摘要持久化成资产，只在源正文变化时才重生成 | 用户改个错别字不会作废摘要、白烧一次调用；判据用字节数而不是 `updatedAt` | `ai_note_summaries.sourceBytes`、`staleRatio = 0.20` |
| 切片每次保存都重切（`staleRatio = 0.0`） | 代价是每次保存多切一次（纯函数 + 一次事务内删/插）；换来片永远指向当前正文 | `note_chunk_repository.dart` |
| 卡片流按缺口补池（一次最多 6 路并行单卡），素材窗口 400 字 | 池子只差一点就只要一点；每路单卡并行，比"一个请求里要一批"快得多 | `feed_repository.dart`（`kFeedPoolTarget` / `kFeedReserveSize` / `kGenParallelism`）、`feed_window.dart` |
| system prompt 前缀稳定 | 时间戳、随机 ID、笔记 ID 一律不进 prompt 开头，变化的东西 append 在末尾——缓存命中后输入价降到 1/50 | `prompts.dart`、[AI接入设计](AI接入设计.md) |
| 轮数、提问数、批量条数、重试次数都有上限 | `maxRounds = 15`、`maxAsksPerTurn = 5`、批量 ≤10、生成类最多重试 1 次 | `agent_loop.dart`、[AI接入设计](AI接入设计.md) |
| `ai_calls` 审计表不存 prompt / 响应全文 | 成本可见性只留 token 与金额，不留内容 | `tables.dart` |
