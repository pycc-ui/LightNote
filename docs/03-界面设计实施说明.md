## 1. 与设计稿的四处偏差（都是经过确认的决定）

| # | 设计稿 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | 数据库用 `sqflite` | **Drift**（构建在 SQLite 之上） | 已确认保留。Drift 需要类型安全的多表关系与响应式 Stream 查询；现有数据层与测试已跑通，重写收益低 |
| 2 | 目录结构 `ui/domain/data/services` | **feature-first**（`features/xxx/{data,ui,domain}`） | 已确认保留。避免大范围改 import 路径（本机无法编译验证，手工改路径风险高） |
| 3 | AI 页只做界面占位，不接真实调用 | **接了真实 DeepSeek**，同时保留隐私约束 | 你最开始的原始需求就是「接入 deepseek api 来整理笔记」。占位实现会让这个核心需求落空 |
| 4 | 底部导航 4 项：轻笔记/笔记库/AI/设置 | 一致，**记忆卡片复习**移入「笔记库 → 更多」 | 底部导航放不下第 5 项；但 SM-2 复习是最初需求的核心能力，不能没有入口，所以放进菜单并显示待复习数量 |
| 5 | 主题种子色 `#4A6FA5`（蓝灰） | **棕色 `#7C522C`** + 棕色羽毛笔图标 | 后续需求把 App 图标定为棕色羽毛笔。图标是棕色、界面主色是蓝色会非常割裂，所以跟着改。**这是唯一一处对设计稿配色的偏离** |
| 6 | 设置页 5 个分区 | 增加**存储位置**与**备份与恢复**两节 | 数据库改为默认放 App 私有目录后，用户看不到也摸不到文件，必须给一个正规的整库导出/导入出口，以及换工作目录的能力。详见第 7 节 |

另：产品名对外统一用 **LightNote**（后续需求指定的唯一命名例外）。
其余标识刻意不变：Dart 包名 `smart_notes`、Windows 可执行文件 `smart_notes.exe`、
数据库文件名 `qing_notes.sqlite`——**改数据库文件名会让老用户的库"凭空消失"**。
Dart 侧身份信息的唯一来源是 `lib/core/app_info.dart`。

另：设计稿 §6.2 的 `Note.tags` 写作「逗号分隔字符串」。笔记的标签改用 **tags 连接表**
（原有实现，且 `usageCount` 热度计数有用）；**卡片级**标签仍按设计稿用字符串存在 `cards.tags`。

## 3. 数据模型对照

设计稿 §6.4 的 SQL 与实际 Drift 表定义（`lib/core/db/tables.dart`）：

| 设计稿表 | 实现 | 说明 |
|---|---|---|
| `folders` | `Folders` | 加了 `sortOrder` 用于同层排序 |
| `notes` | `Notes` | 加了 `excerpt` / `wordCount` / `readingProgress` / `lastAiAt`；`is_deleted` 用 `deletedAt` 时间戳而非布尔（可做回收站时间排序与增量同步） |
| `ai_conversations` | `AiConversations` | `workspace_uri` → **`workspaceFolderId`**，见下节 |
| `ai_messages` | `AiMessages` | 加了 `pendingAction` 字段，为「操作前预览变更」预留 |
| `settings` | `Settings` | 用于搜索历史、主题、字号、自动保存、授权状态 |

另外保留（设计稿未列，因原有功能需要）：`tags`、`note_tags`、`cards`、`reviews`、
`note_summaries`、`ai_calls`、`card_decks`。

### 关于 workspace_uri → workspaceFolderId

设计稿 §8 要求「访问工作目录要用 SAF，选择目录后持久化 URI 权限」。
本次**改为应用内工作区**（工作区 = 本 App 的一个目录），原因：

1. 用 SAF 需要引入 `file_picker` 并处理 `content://` URI 的持久化权限，
   还要处理用户撤销授权的分支——这是一整块独立的复杂度；
2. 本 App 的「工作区」语义实际是「限定 AI 参考哪些笔记」，
   用应用内目录完全能表达，而且不依赖任何第三方包；
3. MVP 阶段先把 AI 闭环跑通，SAF 留到需要读写**外部**文件时再加。

如果你要的是「AI 能读写手机上任意目录的文件」，那这是另一个需求，
需要单独做 SAF 授权流程，告诉我我再加。

## 5. 两个刻意的设计加强

设计稿没有要求，但我在实现时加了两处，因为它们解决的是真实会出问题的地方：

**1. AI 的隐私闸门（`ai_chat_repository.dart`）**

设计稿说「不自动上传」，但没说怎么保证。实现上做了三层：

- 首次使用必须通过一次明确的授权弹窗（可随时在设置页撤销）；
- 每次请求**只发送用户在 `+ → 选择文件` 里显式勾选的笔记**，
  未勾选时只发指令本身，不附带任何笔记正文；
- 发送前输入框上方会显示「本次将发送 N 篇笔记的内容」，让用户随时可核对。

**2. 删除目录不删笔记**

`softDeleteFolder` 在一个事务里做三件事：目录内笔记 `folderId → null` 且 `isInbox → true`
（回到轻笔记）、子目录上浮为顶层、目录本身逻辑删除。
如果直接级联删除笔记，用户整理目录时会一次丢掉一批内容——这是数据丢失事故。

## 6. 存储位置与备份恢复（后续需求新增）

### 6.1 为什么数据库默认放 App 私有目录

原实现按「文档目录 → 支持目录 → 临时目录」的降级链找位置，
结果在受限环境里会**静默落到系统临时目录**——用户重启一次电脑笔记就没了。
现在改成：**默认 App 私有目录**，用户不必也不该去翻它，
数据出口是「导出备份包」而不是文件管理器。

顺序（每一档都**真实试写**再采用）：`QING_NOTES_DB_DIR` 环境变量 →
用户配置的工作目录 → `getApplicationSupportDirectory()/LightNote` →
`getApplicationDocumentsDirectory()/LightNote` → `%USERPROFILE%\LightNote`。
**刻意不把系统临时目录列为候选**：宁可明确报错，也不要静默丢数据。

配置（`storage.json`）存在数据库**之外**的私有目录里。
想放在哪是个先有鸡还是先有蛋的问题：如果"数据库位置"存在数据库里，
那么在打开数据库之前根本读不到它。

### 6.2 备份包格式

```
LightNote-20260213-1045.zip
├── backup.json           清单：formatVersion / appVersion / schemaVersion / 统计 / SHA-256
└── data/qing_notes.sqlite
```

普通 zip，不加密、不私有格式——用资源管理器和 DB Browser 都能打开检查。
**不含 API Key**（它在系统钥匙串里，而备份包常被放进网盘或聊天记录）。

导出用 SQLite 的 `VACUUM INTO` 而不是 `File.copy`：数据库正在被写，
默认 journal 模式下最近一次事务可能还在 `-journal` 文件里，
直接拷主文件可能得到**少了最后一次提交**的库，拷到一半还可能撕裂。

### 6.3 导入为什么要重启

导入时数据库已经打开着。Windows 上打开中的 sqlite 文件既不能改名也不能覆盖；
就算强行换掉，已建立的 drift 连接指向的还是旧文件，之后所有读写都会落到一个
"已经不属于 App"的文件上。所以导入只登记意图（`pending_import.json`），
换库在 `main()` 里、**任何数据库连接建立之前**做，那段代码是纯文件操作。

导入前做三层校验（任一步失败都不写任何数据）：zip/清单合法性 → SHA-256 比对 →
文件头 + `PRAGMA integrity_check` + 必需表检查。

### 6.4 与设计稿的接口差异

设计稿没有这一节。新增的 UI 元素只有三处，都放在设置页：

| 元素 | 说明 |
|---|---|
| 「存储位置」卡片 | 显示真实数据库路径 + 是否私有 + 降级原因；按钮「更换工作目录」 |
| 「导出备份包（.zip）」 | 系统保存对话框选位置；也在私有目录留一份 |
| 「从备份包导入」 | 选 zip → 校验 → 选「覆盖 / 保留」→ 重启换库 |

「选位置」用 Flutter 官方的 `file_selector`（Windows 走 `IFileDialog`，
Android 走 SAF），**不需要申请任何存储权限**。
