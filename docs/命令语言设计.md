# 命令语言设计

这份文档讲 LightNote AI 助手能执行的命令与脚本语法：**有哪些命令、什么语法、边界在哪、怎么和现有架构对接。**

相关：[AI接入设计](AI接入设计.md)（Agent 循环、工具约定、确认流程）、[数据库设计](数据库设计.md)（笔记与切片的存储）、[软件理念设计](软件理念设计.md)（省 token 的第二要义）。

---

## 1. 为什么换掉 function calling

现在的做法：22 个工具以 JSON Schema 形式放在 API 的 `tools` 参数里，每轮重发。

| 问题 | 量级 |
|---|---|
| 工具定义每轮固定开销 | 约 3000-5000 token |
| 多轮往返成本 | O(N²)（每轮重发历史） |
| AI 对 JSON Schema 的熟悉度 | 中等 |

**换成的方案**：把 22 个工具收敛成 1 个「执行脚本」工具，脚本里是 AI 天然熟悉的 shell 风格命令。

| 收益 | 效果 |
|---|---|
| 工具定义 | 22 个 → 1 个（约 250 token） |
| 每轮固定开销 | 3000-5000 → 约 550 token |
| 轮数 | N 轮 → 1 轮（脚本批处理） |
| AI 熟悉度 | shell 是海量训练数据，零学习成本 |

## 2. 整体架构

```
用户提问
  ↓
AI 返回 tool_calls（1 个 run 工具，参数是一段脚本）
  ↓
App 解析脚本 → 逐条执行命令 → 汇总结果
  ↓
结果回灌给 AI（role: tool）
  ↓
AI 分析结果 → 要么再发一次 run，要么给出回答
```

**只保留 1 个工具 `run(script)`。** 所有操作都在脚本里。

## 3. 工具定义

`tools` 参数里只放一个：

```json
{
  "type": "function",
  "function": {
    "name": "run",
    "description": "在用户的笔记库上执行命令脚本。支持 ls/stat/sed/grep/echo/rm/mkdir/mv。可写多行，用 for/if 做简单批处理。只读命令批量执行，写命令逐条弹确认。",
    "parameters": {
      "type": "object",
      "properties": {
        "script": {
          "type": "string",
          "description": "命令脚本，每行一条命令。语法见 system prompt。"
        }
      },
      "required": ["script"]
    }
  }
}
```

约 250 token，替代原来的 3000-5000。

## 4. 命令清单（9 个）

### 4.1 浏览

| 命令 | 作用 |
|---|---|
| `ls [库]` | 列笔记库，或某库内笔记（只给名字） |
| `stat <笔记>` | 笔记元信息：行数、字数、大小、时间、所属库 |

`stat` 必须给出**行数**——这是 `sed` 定位的基础，AI 靠它决定要不要分次读。

### 4.2 读取

| 命令 | 作用 |
|---|---|
| `sed -n 'A,Bp' <笔记>` | 读第 A 到第 B 行 |
| `grep "词" [路径]` | 搜索，返回**行号 + 片段** |

`grep` 必须返回行号——这是去掉「片」之后，AI 定位长笔记的唯一途径。

### 4.3 修改（全部走 sed）

| 命令 | 作用 |
|---|---|
| `sed 'A,Bc 新内容' <笔记>` | 替换第 A-B 行 |
| `sed 'A,Bd' <笔记>` | 删除第 A-B 行 |
| `sed 'Ai 新内容' <笔记>` | 在第 A 行前插入一行 |
| `sed 'Aa 新内容' <笔记>` | 在第 A 行后追加一行 |

**`c` / `d` / `i` / `a` 是真实 sed 语法，AI 零学习成本。**

### 4.4 整篇写入

| 命令 | 作用 |
|---|---|
| `echo "内容" > <笔记>` | 新建 / 覆盖整篇 |
| `echo "内容" >> <笔记>` | 追加到末尾 |

### 4.5 管理

| 命令 | 作用 |
|---|---|
| `rm <笔记>` | 删除笔记（不可恢复） |
| `mkdir <库>` | 新建笔记库 |
| `mv <笔记或库> <目标>` | 移动 / 重命名 |

## 5. 脚本语法（4 个原语）

**语法明显不是 bash**——用 `set` / `:` / `end` 这三个关键词，AI 一眼看出这不是 shell，不会往里套 bash 特性。

### 5.1 变量定义

```
set 名字 = 值
```

- 名字只能用中文、英文、数字、下划线
- 定义后可用 `$名字` 引用

### 5.2 变量引用

```
$名字
```

- 可以单独用：`ls $库`
- 可以拼接：`"$库/$笔记"` 或 `$库/$笔记`
- 引用不存在的变量 → 报错，不静默变空串

### 5.3 循环

```
for 变量 in 列表
  ...
end
```

- 列表可以是命令结果（如 `ls $库`），也可以是字面量列表 `"a" "b" "c"`
- 支持**一层**循环，不支持嵌套

### 5.4 条件

```
if 命令
  ...
end
```

- 命令执行成功（退出码 0）→ 执行 if 体
- 支持**一层**条件，不支持嵌套、不支持 `else`

### 5.5 注释

```
# 这一行是注释
```

`#` 开头的整行是注释。**不支持行尾注释。**

## 6. 明确不支持清单（边界定义）

**以下一律不支持。写了就报错。**

```
✗ 管道                ls | grep
✗ 命令替换            $(ls)
✗ 反引号               `ls`
✗ 通配符              * ? [a-z]
✗ 正则                grep "^风险.*"
✗ 算术运算            1 + 1、$((x+1))
✗ 字符串函数          substr、replace、split
✗ 函数定义与调用
✗ 嵌套循环            for ... for ... end end
✗ 嵌套条件            if ... if ... end end
✗ else / elif
✗ while / until
✗ break / continue / return
✗ 重定向（除 > 和 >> 外）
✗ 后台执行            &
✗ 多命令一行          ls; stat
✗ 逻辑运算符          && ||
✗ 环境变量            export、$PATH
✗ 多行字符串
✗ 行尾注释            ls # 注释
✗ 任何未列出的命令
```

**需要重复用 `for`，需要决策用 `if`，其它一律展开写。**

### 6.1 多行插入怎么办

**写多条 `sed`。** 不引入多行字符串——一旦支持多行，转义、换行、缩进的解析复杂度会翻倍。

```
sed '5a 第一行' 会议记录
sed '6a 第二行' 会议记录
sed '7a 第三行' 会议记录
```

## 7. System Prompt

`run` 工具的描述之外，system prompt 里要放一段命令说明：

```
你可以在用户的笔记库上执行命令。

结构：根目录下是笔记库，笔记库下是笔记。
根目录固定有一个"我的轻笔记"，存放未归档的笔记。

语法：
  set 名字 = 值            定义变量
  $名字                    引用变量
  for x in 列表 : ... end  循环
  if 命令 : ... end        条件
  # ...                    注释

命令：
  ls [库]                  列库 / 列笔记
  stat <笔记>              行数、字数、时间、所属库
  sed -n 'A,Bp' <笔记>     读第 A-B 行
  sed 'A,Bc 新内容' <笔记>  替换第 A-B 行
  sed 'A,Bd' <笔记>        删除第 A-B 行
  sed 'Ai 新内容' <笔记>    在第 A 行前插入一行
  sed 'Aa 新内容' <笔记>    在第 A 行后追加一行
  grep "词" [路径]         搜索，返回行号 + 片段
  echo "内容" > <笔记>     新建 / 覆盖
  echo "内容" >> <笔记>    追加
  rm <笔记>                删除
  mkdir <库>               新建笔记库
  mv <笔记> <库>           移动 / 重命名

执行方式：命令写在一个 run 脚本里，一次可以写多行。
能一次做完的事不要拆成多轮。
读长笔记：先 stat 看行数，再 grep 定位，最后 sed 读那几行。
要改笔记：必须先用 sed -n 读出目标行，确认行号，再在同一脚本里改。
写命令会弹确认框；删除不可恢复。

不支持：管道、命令替换、通配符、正则、算术、函数、
嵌套控制流、else、while、&&、||、多行字符串、行尾注释。
需要重复用 for，需要决策用 if，其它一律展开写。
```

**约 400 token。**

## 8. 执行规则

### 8.1 一次输出一批

AI 把要执行的所有命令写在**一个** `run` 调用里。

### 8.2 读命令批量执行

`ls` / `stat` / `sed -n` / `grep` 批量执行，结果一次性返回。

### 8.3 写命令逐条确认

`echo` / `sed` 的 c/d/i/a 动作 / `rm` / `mkdir` / `mv` **每条都弹确认框**，用户允许才执行。

**脚本里混了写命令时：**

```
$ ls 工作笔记          ← 执行
$ stat 会议记录        ← 执行
$ rm 周会              ← 暂停，弹确认框
```

用户允许后继续，拒绝后**跳过这一条，继续下一条**（不中断整个脚本）。

### 8.4 出错处理

- 单条命令失败：返回错误信息，**继续执行下一条**
- 语法错误（如 `if` 没有配对的 `end`）：整段脚本拒绝执行，返回错误位置
- 引用未定义变量：报错并停止整段脚本

### 8.5 读改连续原则

**`sed` 修改行号定位。要用 sed 改笔记时，必须在同一个脚本里先用 `sed -n` 读目标行，拿到行号后再改。**

读和改在同一脚本里连续执行，行号不会漂移。单用户本地场景下，用户在脚本执行中间改笔记的可能性为零。

写进 system prompt。

### 8.6 执行上限

| 项 | 上限 |
|---|---|
| 单次脚本命令条数 | 50 |
| 单次 `sed -n` 读行数 | 200 |
| 单次 `grep` 返回条数 | 50 |
| 单次 `for` 循环次数 | 100 |
| 单次脚本总耗时 | 10 秒 |

超限：截断并提示"结果已截断，请缩小范围"。

## 9. 错误信息格式

**所有错误都要教 AI 怎么改。**

```
$ cat 会议记
错误：没找到笔记"会议记"。
当前库"工作笔记"里有：会议记录、周会、项目A。
提示：检查笔记名是否写错，或先用 ls 查看。

$ sed '100c 新内容' 会议记录
错误：笔记"会议记录"只有 45 行，第 100 行不存在。
提示：先用 stat 确认行数，再 sed -n 读目标行。

$ sed '12c 新内容' 不存在的笔记
错误：没找到笔记"不存在的笔记"。
提示：先用 ls 查看有哪些笔记。
```

**错误信息必须带**：

1. 出错原因
2. 当前状态（有哪些候选、实际行数是多少）
3. 下一步建议

## 10. 完整示例

### 10.1 读长笔记的风险部分

```
stat 工作笔记/项目A
grep "风险" 工作笔记/项目A
sed -n '143,149p' 工作笔记/项目A
sed -n '208,214p' 工作笔记/项目A
```

### 10.2 修改某行 + 插入两行

```
stat 工作笔记/会议记录
sed -n '10,14p' 工作笔记/会议记录
sed '12c 项目A的截止日期是下周一中午前' 工作笔记/会议记录
sed '12a 补充1：下周一需确认资源和人员' 工作笔记/会议记录
sed '13a 补充2：会议纪要将同步给所有相关方' 工作笔记/会议记录
```

### 10.3 插入空行

```
sed '5a ' 会议记录
```

（`a` 后面跟空格即插入空行）

### 10.4 批量统计

```
set 库 = "工作笔记"
set 总数 = 0

for 笔记 in ls $库
  if grep "项目A" $库/$笔记
    echo "$笔记" >> 项目A汇总
    set 总数 = $总数 + 1
  end
end

echo "共 $总数 篇" >> 项目A汇总
```

## 11. 和现有架构的对接

### 11.1 不改动的部分

| 模块 | 说明 |
|---|---|
| `AgentLoop` | 循环驱动完全不动 |
| 风险分级（`ToolRisk`） | 在**命令粒度**上声明（`rm`=delete、sed 的 c/d/i/a=modify……） |
| 确认层 | 写命令逐条弹确认，不变 |
| 撤销栈 | 修改类命令仍进撤销栈 |
| 读片预算 | `sed -n` 的读行数上限替代原来的片预算 |
| 会话历史、摘要、挂起 | 全部不动（`askUser` 保留，是挂起的载体） |

> **工作区已取消**（后续定案）：原先"命令只能访问工作区内的笔记"这条不再成立 ——
> AI 直接作用于**整个笔记库根目录**。AI 页选工作区的位置改成了**选模型**
> （flash / pro），卡片流固定 flash。

### 11.2 改动的部分

| 模块 | 改成 |
|---|---|
| `tool_specs.dart` | 22 个工具 → `run` + `askUser`（后者保留，挂起用） |
| `tool_executor.dart` | 加 `run` 分支，内部调命令解析器 |
| `agent_loop.dart` | 去掉分层发送 / `requestTools` / 工具目录 |
| system prompt | 加命令语法说明（`AiPrompts.agentSystem`） |

### 11.3 新增的部分

| 模块 | 作用 |
|---|---|
| 命令解析器 | 分词、白名单校验 |

## 12. 落地顺序

### 第 1 步：单命令模式

先实现 9 个命令的 handler + 一个简单的解析器（一次一条命令，不支持脚本）。验证命令本身工作正常。

### 第 2 步：多行批处理

支持一个脚本里写多行命令，逐条执行，结果汇总。

### 第 3 步：脚本解释器

加变量、循环、条件。写单元测试覆盖语法边界。

### 第 4 步：接进 AgentLoop

把 `run` 工具接进现有的工具执行流程。保留 `function calling` 作为 fallback（通过配置切换）。

### 第 5 步：对比数据

同一批任务，对比新旧方案的：
- token 消耗
- 成功率
- 用户满意度

数据说话再决定是否切主路径。

## 14. 一句话

**1 个 `run` 工具 + 9 个命令 + 4 个语法原语。**  
命令全部是 AI 熟悉的 shell 语义（`ls` / `stat` / `sed` / `grep` / `echo` / `rm` / `mkdir` / `mv`），语法用 `set` / `:` / `end` 明确区别于 bash。**每轮固定开销从 3000-5000 token 降到约 550，轮数从 O(N²) 降到 O(N)。** 风险分级、确认层、撤销栈全部保留（**工作区已取消**：AI 直接作用于整个笔记库根目录）。**边界一页文档写清，永不越界。**

> **落地补充（与本文并行定案）**：AI 页选工作区的位置改成选模型（flash / pro），
> 卡片流固定 flash；卡片正文 400–800 → 200–400 字；摘要硬上限 220 → 120 字；
> 卡片生成 `maxTokens` 16384 → 2048；片内窗口 400 → 300 字；切片只服务卡片流
> 与搜索，**不再给 AI Agent**（Agent 改走 `sed` / `grep` 按行号读写）。
