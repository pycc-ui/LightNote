# 数据模型设计

> 全部表定义在 [`lib/core/db/tables.dart`](../lib/core/db/tables.dart)，数据库类在 [`lib/core/db/app_database.dart`](../lib/core/db/app_database.dart)。
> 本文件是表结构的唯一说明来源——**改表先改这里，再改代码**。

---

## 1. ER 关系

```
notes ──1:N──> cards ──1:N──> reviews
  │              │
  │              └─ card_source: ai / manual
  │
  ├──N:M──> tags        （通过 note_tags 连接表）
  │
  ├──1:N──> note_summaries   （AI 生成摘要，可多版本/多模型）
  │
  └──1:N──> ai_calls         （成本与调试审计）

card_decks  独立的分组维度（可选，用于按主题筛选复习）
```

设计原则：

1. **逻辑删除**：`notes.deleted_at` 非空即视为已删除。同步与回收站都依赖它，比物理删除安全。
2. **时间统一 UTC**：所有 `DateTime` 列以 UTC 存储，展示层再转本地时区。跨时区/夏令时不会错位。
3. **AI 产物与原文分离**：AI 摘要、卡片都不是笔记正文的一部分，单独表存储，可整体丢弃重算。
4. **为未来算法预留字段**：`cards.stability` / `cards.difficulty` 现在是 0，迁移 FSRS 时直接启用，不用改表。

## 2. notes（笔记主表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | UUID v4，不用自增——同步时不冲突 |
| title | TEXT | — | 允许空，列表页显示"无标题" |
| content | TEXT | — | Markdown 原文 |
| contentFormat | TEXT | default 'markdown' | `markdown` / `plain` |
| excerpt | TEXT | — | 前 200 字纯文本，列表页预览，避免读全文 |
| source | TEXT | default 'manual' | `manual` / `import` / `share`（分享进来） |
| pinned | BOOL | default false | 置顶 |
| archived | BOOL | default false | 归档，不出现在默认列表 |
| readingProgress | REAL | default 0 | 0.0–1.0，阅读位置 |
| readingSeconds | INT | default 0 | 累计阅读秒数，用于"阅读时长"统计 |
| wordCount | INT | default 0 | 写入时计算并缓存 |
| lastAiAt | DATETIME | nullable | 上次 AI 整理时间，UI 用来显示"已整理"角标 |
| createdAt | DATETIME | default now | |
| updatedAt | DATETIME | default now | **每次写入必须更新**，同步靠它 |
| deletedAt | DATETIME | nullable | 逻辑删除标记 |

索引：

- `idx_notes_updated` on `(updated_at DESC)` —— 默认列表排序
- `idx_notes_pinned` on `(pinned, updated_at DESC)` —— 置顶优先
- `idx_notes_deleted` on `(deleted_at)` —— 过滤已删除

## 3. tags / note_tags（标签）

### tags

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | UUID |
| name | TEXT | **UNIQUE** | 显示名 |
| normalizedName | TEXT | **UNIQUE** | 小写去空格，防止 "Flutter" 和 "flutter" 分裂成两个标签 |
| colorValue | INT | nullable | 标签色 |
| usageCount | INT | default 0 | 冗余计数，标签云按热度排序时避免 COUNT(*) |
| createdAt | DATETIME | default now | |

> **`usageCount` 是刻意的反范式**。标签列表页每次都要按使用次数排序，关联表 COUNT 在笔记量大时会变慢。代价是增删标签关联时必须同步维护，已在 `NoteRepository` 的标签方法里集中处理。

### note_tags（连接表）

| 字段 | 类型 | 说明 |
|---|---|---|
| noteId | TEXT | → notes.id |
| tagId | TEXT | → tags.id |
| createdAt | DATETIME | |

主键：`(noteId, tagId)` 复合主键，天然去重。外键均 `ON DELETE CASCADE`。

## 5. cards（记忆卡片）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | TEXT | PK | UUID |
| noteId | TEXT | nullable, FK→notes | 手动创建的卡片可以为空（独立卡片） |
| deckId | TEXT | nullable, FK→card_decks | |
| question | TEXT | — | 正面 |
| answer | TEXT | — | 背面，支持 Markdown |

| aiModel | TEXT | nullable | 记录是哪个模型生成的，便于评估质量 |
| tags | TEXT | nullable | 逗号分隔的轻量标签（卡片级，不走 tags 表） |

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| dueAt | DATETIME | now | 下次到期时间；**复习队列按它排序** |
| intervalDays | INT | 0 | 当前间隔（天） |
| ease | REAL | 2.5 | 难度因子 EF，范围 1.3–2.8 |
| repetitions | INT | 0 | 连续答对次数；=0 表示新卡 |
| lapses | INT | 0 | 累计遗忘次数 |
| lastReviewedAt | DATETIME | nullable | |
| reviewCount | INT | 0 | 总复习次数 |
| suspended | BOOL | default false | 暂停，不进入队列 |

### 预留（FSRS 迁移用）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| stability | REAL | 0 | FSRS 稳定性，当前算法不写 |
| difficulty | REAL | 0 | FSRS 难度，当前算法不写 |

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| createdAt / updatedAt | DATETIME | now | |
| deletedAt | DATETIME | nullable | |

索引：

- `idx_cards_due` on `(suspended, due_at)` —— 今日待复习查询的主力索引
- `idx_cards_note` on `(note_id)` —— 打开笔记时列出它的卡片

## 6. reviews（复习流水）

**追加写，永不更新**。这是可回放的事实表——将来换 FSRS 要用它来拟合参数，也能做学习曲线统计。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | PK |
| cardId | TEXT | → cards.id, CASCADE |
| quality | INT | 1 / 3 / 4 / 5 |
| easeBefore / easeAfter | REAL | 便于审计算法行为 |
| intervalBefore / intervalAfter | INT | |
| elapsedMs | INT | 从看到卡片到评分耗时，可用于识别"瞎点" |
| reviewedAt | DATETIME | |

索引：`idx_reviews_card` on `(card_id, reviewed_at DESC)`。

## 7. note_summaries（AI 整理结果）

一次整理产生一条记录，**不覆盖历史**——用户可以对比不同模型/不同时间的结果。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | PK |
| noteId | TEXT | → notes.id, CASCADE |
| model | TEXT | 如 `deepseek-flash` |
| oneLine | TEXT | 一句话摘要（列表页和阅读页顶部用） |
| bullets | TEXT | **JSON 数组字符串**，要点列表 |
| suggestedTags | TEXT | JSON 数组字符串 |
| actionItems | TEXT | JSON 数组字符串，待办/行动项 |
| rawResponse | TEXT | nullable，原始返回，调试用 |
| promptTokens / completionTokens | INT | 用量 |
| costCents | REAL | 估算成本（分），设置页汇总 |
| createdAt | DATETIME | |

> `bullets` 等用 JSON 字符串而不是独立子表：这些数据只整体读写、不单独查询，拆表只会增加 JOIN。若将来需要"按要点搜索"，再迁移到子表。

## 8. ai_calls（调用审计）

记录每一次 API 调用，用于成本可见性和故障排查。

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | PK |
| noteId | TEXT | nullable |
| task | TEXT | `summarize` / `generate_cards` / `ask` / `organize` |
| model | TEXT | |
| thinkingEnabled | BOOL | 是否开了思考模式 |
| promptTokens / completionTokens | INT | |
| costCents | REAL | |
| latencyMs | INT | |
| success | BOOL | |
| errorCode | TEXT | nullable，如 `401` / `429` / `timeout` / `json_empty` |
| createdAt | DATETIME | |

**隐私约束**：本表**不存 prompt 与响应全文**，只存用量与状态。`note_summaries.rawResponse` 是唯一的原文留存点，且在设置页提供"清空 AI 历史"入口。

## 9. 「今日待复习」查询

```sql
SELECT c.*
FROM cards c
WHERE c.suspended = 0
  AND c.deleted_at IS NULL
  AND c.due_at <= :endOfTodayUtc
ORDER BY c.due_at ASC
LIMIT :limit;
```

新卡限量策略（在 Dart 层做，避免复杂 SQL）：

```
优先取所有到期旧卡；
若队列长度 < dailyNewLimit(默认 15)，从 repetitions = 0 的卡里按 createdAt 补足。
```

对应 Drift 写法见 [`lib/features/cards/domain/review_scheduler.dart`](../lib/features/cards/domain/review_scheduler.dart) 与 `AppDatabase` 的 `watchDueCards`。

## 10. 迁移策略

Drift 用 `schemaVersion` + `MigrationStrategy`：

```dart
@override
int get schemaVersion => 1;

@override
MigrationStrategy get migration => MigrationStrategy(
  onCreate: (m) => m.createAll(),
  onUpgrade: (m, from, to) async {
    // 每个版本一段，只做增量，不重写历史
    // if (from < 2) { await m.addColumn(notes, notes.someNewColumn); }
  },
);
```

规则：

1. **永不修改已发布的迁移分支**，只追加新版本号。
2. 每次改表后导出 schema：`dart run drift_dev schema dump lib/core/db/app_database.dart drift_schemas/`，并写迁移测试。这样能在 CI 里自动发现"改了表但忘了写迁移"。
3. 加列时给默认值或允许 NULL，避免老数据插入失败。
