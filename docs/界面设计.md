# 界面设计

本文只讲**界面**：有哪几屏、每屏的关键交互、视觉与提示规范。
文中路径都相对项目根，并且**以 `lib/` 下的真实代码为准**——文档与代码不一致时改文档。

相关：[目录设计](目录设计.md)（文件放哪、各自什么职责）、[软件理念设计](软件理念设计.md)（为什么功能上做减法）。

## 1. 信息架构

```
底部导航（3 个位置，lib/app/app_shell.dart）
├── 轻笔记     AI 从素材里生成的新卡片（消费端，不产出内容）
├── 笔记库     笔记库（平铺）+「我的轻笔记」区块；右下角两个 FAB（上：AI 助手，下：新建）
└── 设置       只做导航，见 §3.9

其他入口
├── 搜索        笔记库页顶栏（全局，含「我的轻笔记」）/ 笔记库详情页顶栏（只搜本库）
├── 素材来源     轻笔记页右上角调节图标（Icons.tune）
├── AI 助手      笔记库页右下角、新建 FAB 上方
├── 轻笔记详情   点卡片流里的卡片
├── 笔记库详情   笔记库 → 点某个笔记库
└── 笔记编辑     点任意笔记（进阅读态）；新建走笔记库页 `+` / 笔记库详情页 `+`
```

**AI 不进底部导航**：它是"偶尔进去问一次"的助手，不该和三个主页面平级的常驻 tab 并列。
入口放在笔记库页右下角、新建 FAB 上方——它和"新建"同属"一个动作入口"，
放在一起既不抢主流程，又随时够得着。

### 一个重要的语义分工

「轻笔记」这个词出现两次，**指的不是同一批内容**：

| 位置 | 内容 |
|---|---|
| 底部导航的**轻笔记页** | AI 从选定素材里**新生成**的卡片（看完可以收下，也可以直接走掉） |
| 笔记库页的**「我的轻笔记」区块** | **未归档**笔记（`is_inbox = true`，尚未归入任何笔记库） |

两者的关系是**单向**的：轻笔记 →（点「加入我的轻笔记」）→ 我的轻笔记；反过来不成立
（「我的轻笔记」的笔记不会变成卡片流里的内容——卡片流只从素材**新生成**）。
所以它们叫法再像也不是同一批东西：**一个页面在"生成"，另一个区块在"存放还没归档的笔记"。**

**速记（随手记）的入口在笔记库页**，不在轻笔记页——消费流不产出内容。
所以"随手记一句"走笔记库页 `+` →「新建笔记到「我的轻笔记」」。

## 3. 各屏关键交互

### 3.1 轻笔记页：AI 卡片流

**卡片上只有标题**（最多 3 行，超出省略），另有：

- 一行「点开看全文 ›」提示——卡片上只有标题，必须让用户知道还有下文；
- 左下角一个**短标签**（生成结果里的第一个标签）；没有标签时退回「AI 生成」；
- 右下角是一个**开关式按钮**：未收下时「加入我的轻笔记」，收下后变「从我的轻笔记移出」。

标题为空时占位显示「（无标题）」。

卡片高度**自适应**：内容少就按内容高，最多到屏高 2/3（下限 445），不写死像素。
一屏基本只完整显示一张，下一张露头提示"下面还有"。
固定成 2/3 屏是试过的，效果很差：1 行标题的卡片也占满 2/3 屏、中间一大片空白。
改成自适应之后还踩过一个坑——用 `Spacer` 撑底部会把 `Column` 拉到上限高度，
正确做法是 `spaceBetween`（内容本来就矮时不会额外撑高）。

| 用户动作 | 结果 |
|---|---|
| 下拉（RefreshIndicator 的圆圈） | **前向追加**：新的 3 张插到列表**最前面**（3 → 6 → 9…，累积） |
| 滚动到底 | **什么都不做**（没有上拉加载，也没"滚到底自动加载"） |
| 点卡片 | 进**轻笔记详情页**看全文（卡片内容此刻还没落库） |
| 点「加入我的轻笔记」 | 立刻写出一条未归档笔记，提示「已加入「我的轻笔记」」；按钮变「从我的轻笔记移出」 |
| 点「从我的轻笔记移出」 | 删掉那条笔记（逻辑删除），提示「已从「我的轻笔记」移出」 |

"已加入"**从数据库实时推导**（按标题+正文指纹，或本次会话记住的 noteId），不记在页面内存里：
用户跑到笔记库页把它删了，卡片这边会跟着变回「加入」。

**为什么卡片上不放正文预览**：两种做法都试过并都放弃了——截正文前 N 字，读起来就是"被截断的正文"；
让 AI 单独生成一段摘要，要维护两个内容字段，而且**模型根本不守字数**（要求 45–60 字，稳定返回 116–160 字）。
于是卡片只剩标题，标题就得一个人承担"让人想点进去"的责任：提示词里专门要求它是**一句有钩子的话**，
而不是「间隔重复」这种干标签。左下角那一格也因此给了标签——按钮文案已经能表达加入状态，
用户更想知道的是"这条在讲什么"。

**为什么加入之后按钮变成「移出」而不是变灰**：早先是加入后置灰禁用，用户以为坏了——
其实是想撤销收下，却没有入口。现在它是个开关，两个方向都点得动。

**每次看到的内容为什么不一样**

卡片不是"已有笔记的视图"，每张卡片都是 **AI 就某一份素材现写的新内容**。一份素材有两样东西：

| 内容 | 是什么 | 性质 |
|---|---|---|
| **摘要** | 这篇笔记的整体背景 | AI 生成、**存库长期复用**（硬上限 300 字） |
| **原文切片里的 400 字窗口** | 具体内容 | 原文，**不失真** |

切片是给搜索与 AI 用的**语义单元**（按标题层级切，上限 700 字；代码块 / 表格 / 列表不拆散，
是唯一允许超上限的例外。见[数据库设计](数据库设计.md) 第 9 节）；
卡片流是消费侧，只从片里开一个 **400 字**的窗口（`FeedWindow`）——片不足 400 字就是整片。
用户看不到"片"，能感觉到的只有一件事：**同一篇笔记被反复抽到时，看到的段落在往后走。**

| 机制 | 用户看到的效果 |
|---|---|
| 窗口起点候选 `0 / 400 / 800 …`，**最后一个窗口尾部对齐** | 长笔记的尾段也一定被取到，不会只剩几十个字 |
| 用掉一个窗口后，下次从**下一个候选起点**开始（环形） | 一篇长笔记不会永远只出开头那 400 字 |
| `note_chunks.last_used_at` **落库**，取片时"最久没用过的排前面，从没用过的排最前" | 重启 App 也不会又抽到刚看过的那批片 |
| 会话内再记一层"最近用过的片"（60 个） | 同一会话里短期重复更少 |
| **来源冷却**：最近 12 张卡片里，同一篇笔记最多出现 1 次 | 连着两批不会都在讲同一篇笔记 |

所以**前后两次看到的内容不完全一样**：素材是打乱后随机取的，窗口在片内往后轮换，
用过的片还有持久化记录兜着——这几层合起来，同一个位置、同一篇笔记很难被连着抽到两次。

标题层面还有三道防线，用户看到的是"卡片标题不重样"：取片时跳过最近用过的片 →
把**已经生成过的标题**列进提示词让模型主动避开 → 生成后把标题太像的草稿**直接丢掉**
（按"去掉标点/空白/大小写后只留实义字符"比指纹，「抄书是最没用的努力」和「抄书是最没用的努力！」算同一张）。

素材本身还做了两件事：

- 库里笔记少时，同一篇笔记的**不同片**会被当成不同素材（每片说的是不同的事），
  所以"只有 3 条笔记"也凑得出一批卡片；片也不够时由提示词让模型从不同角度补足张数；
- 摘要**第一次抽中某篇笔记时才生成**（不为永远抽不到的笔记提前花钱）；
  正文**字节数变化超过 20%** 才认为摘要过期（改个错别字不会白烧一次 token）；
  摘要生成失败就**退回正文截断**——摘要只是省钱的优化，不该成为"生成不出卡片"的单点故障。

**跨启动预留：为什么第二次打开就快了**

- 首次装完 App：要等一次生成（约 5~10 秒），这段时间显示骨架屏；
- 之后进入：先把**上次留在库里**的 6 张放进池子（前 3 张立刻当第一屏，**秒出**），
  同时后台再补一批、并把末尾几张留给再下次。预留在库里是"消费即清 + 整批替换"，
  所以不会重复看到同一批。

池子常备 12 张、一屏取 3 张，取完立刻在后台补：用户连刷 4~5 次才会碰到池子空。
生成结果不落库，**唯一存下来的只有每篇笔记的 AI 摘要与这份预留**——
卡片是"随手刷到的东西"，不是收藏品。

页面状态：

| 状态 | 表现 |
|---|---|
| 首次加载 | 骨架屏：3 个灰块（约 200 高、卡片圆角），不用转圈 |
| 未选来源 | 「还没有选择素材来源」+ 按钮「选择笔记库」（完整文案见 §6） |
| 选了但无素材 | 「选中的来源没有可用素材」+ 按钮「换个来源」（完整文案见 §6） |
| 生成失败 | 「生成失败」+ 原因 + 按钮「重试」 |
| 已有卡片时刷新失败 | **不清空已有卡片**，只弹一条 error 提示「生成失败：<原因>」 |
| 来源被全部取消 | 立刻切回「还没有选择素材来源」的引导；屏幕上已有的卡片**不清空** |

**两类引导的分界**（`FeedSource.isEmpty`）：只有"笔记库一个都没勾 **且** 关掉「包含我的轻笔记」"才算"没选来源"。
只关掉一边（比如笔记库全不勾、但「包含我的轻笔记」还开着）**不算**没选来源，
这时若库里没有正文非空的笔记，落到的是「选中的来源没有可用素材」。
空正文的笔记**直接跳过**，不参与生成。

**从素材来源页返回**（只有真的改了才会返回"有变化"）：

1. 丢掉数据层里那批用旧来源生成的池子——留着的话下次取卡片还是旧来源的内容；
2. **屏幕上已经显示的卡片保留**：用户只是改了个设置，不该清空他正在看的东西；
3. 重新解析一次来源，如果一个来源都不剩，立刻切回「还没有选择素材来源」引导；
4. **只有本来就没有卡片时**才立刻取一屏；有卡片就什么都不做，等用户自己下拉。

未配 API Key 时：预热会安静失败，页面照走按需生成；真发不出去就落到「生成失败」+ 原因，不是静默空白。

### 3.2 轻笔记详情页

- 顶部标题、一行「AI 从你的笔记库生成」、下面 Markdown 渲染的全文（只读，没有编辑概念）；
- 顶栏右侧：未收下时是「加入我的轻笔记」（点击时按钮内显示转圈），收下后变成绿色的「已加入」；
- 返回时把"收下没有"带回列表，让卡片立刻显示成已加入；
- 加入失败弹 error「保存失败：<原因>」。

**这一页（以及卡片上）只有"收下"这一个动作，别无其它**（`feed_detail_page.dart` 的 AppBar 只有一个 action）：

| 有 | 没有 |
|---|---|
| 未收下时「加入我的轻笔记」（点击时按钮内转圈），收下后变成绿色的「已加入」 | **没有笔记库选择器**：收下只会写进「我的轻笔记」，不能一步归到某个笔记库 |
| 返回（把"收下没有"带回列表） | **没有新建笔记的入口**，也没有编辑 / 删除 / 更多菜单（卡片上同样只有「加入 / 移出」一个开关） |

所以"轻笔记长出笔记"这条链在**归档那一步是断的**：卡片能生成、能看全文、能收进「我的轻笔记」，
但要归进某个笔记库，用户必须再进笔记库页或编辑页操作一次（见 §9.5）。

### 3.3 素材来源页

- 说明文字：勾选作为素材的笔记库，**以后新建的笔记库会自动加入**，除非在这里取消勾选；
- 「包含我的轻笔记」开关（把未归档笔记也当素材）；
- 笔记库清单是**平铺复选**（笔记库没有层级，不存在父子级联问题）；
- 顶栏：全选 / 全不选、保存；页面底部另有「恢复默认」——**清掉用户存的排除集**（回到"我从没表过态"），
  没有它用户就再也回不到"新库自动加入"的状态；
- **选择与进来时完全一致时直接返回、不写库**：否则用户打开这页点一下保存就会被记成"用户接管了来源"，
  之后新建的笔记库永远不再自动进来；
- 允许保存空选择，只提示一句「没有选任何来源，卡片流会是空的」。

**页面上写死的文案**（`feed_source_page.dart`）：

| 位置 | 文案 |
|---|---|
| 页首说明 | 「勾选作为素材的笔记库。AI 会从里面长出新内容。以后新建的笔记库会\*\*自动\*\*加入，除非你在这里取消勾选。」（原文里那对 `**` 是**字面量**，会原样显示——这段文字不是 Markdown） |
| 开关标题 / 副标题 | 「包含我的轻笔记」/「还没归档到任何笔记库的笔记，也拿来当素材」 |
| 分区标题 | 「笔记库」 |
| 无笔记库 | 「还没有笔记库」+「去「笔记库」建一个笔记库，笔记就能按笔记库参与卡片流。」 |
| 恢复默认 | 「恢复默认」/「全部笔记库 + 我的轻笔记，之后新建的也会自动加入」；**已经是默认状态时置灰不可点**（没排除任何库且包含「我的轻笔记」），点成功后提示「已恢复默认来源」 |

**页面上不需要任何"同步/刷新"动作**：用户**取消勾选**的库才会被记住（存的是"用户不要什么"），
没表过态的库——包括之后新建的——一律算勾上。所以"默认全选 + 新库自动进来"是**构造性成立**的，
不是靠某个时机去对账。界面上能看到的效果：在笔记库页新建一个库、切回轻笔记页，它已经在来源里（不用重启）。

### 3.4 笔记库页

结构是「笔记库」区块 + 「我的轻笔记」区块（`SectionHeader`）。

| 元素 | 交互 |
|---|---|
| 笔记库项 | 点进笔记库详情；长按弹菜单：**重命名**、**删除笔记库**（副标题「笔记库内笔记会回到轻笔记」） |
| 笔记库为空 | 「还没有笔记库」+ 按钮「新建笔记库」 |
| 笔记项（我的轻笔记） | 点进阅读态；**左滑删除**；长按弹菜单：移动到笔记库 / 移回轻笔记 / 删除笔记 |
| 我的轻笔记为空 | 「还没有轻笔记。点右下角 + 「新建笔记」随手记一句，之后再归档到上面的笔记库。」 |
| 右下 FAB | 上：AI 助手（`Icons.auto_awesome_outlined`）；下：新建（`Icons.add`） |
| 顶栏 | 搜索（**全局**，含「我的轻笔记」）、「更多」→「多选笔记」 |

**新建 FAB 是三选一**（`showCreateSheet`，第一项最常用所以放最上面且不再追问）：

1. 新建笔记到「我的轻笔记」——随手记一句，之后再归档；
2. 新建笔记并选择笔记库——创建后直接归入某个库；
3. 新建笔记库——建容器，不是建笔记。

新建笔记**不先落库**：把"落到哪个笔记库"作为草稿参数传给编辑页，只有用户真的写了内容才创建。
什么都不写就返回，库里从头到尾没有这条笔记。

**删除的分工（重要）**：

| 动作 | 反馈 |
|---|---|
| 单条左滑删除 | **乐观删除 + 撤销**：立刻删掉，底部提示「已删除「标题」」+「撤销」按钮（3 秒自动走）。左滑本身已经是明确的意图，不再弹确认 |
| 批量删除 | **二次确认**：「删除 N 条笔记」/「这些笔记将被删除，不可恢复。」，红色「删除」；不给撤销（一次删几十条时把完整状态留在内存等撤销代价太大） |
| 删除笔记库 | 确认框写清后果：**不删笔记**，库内笔记会回到「轻笔记」，之后可以再归档到别的库 |

多选模式：顶栏左边关闭、标题「已选 N 条」、右边全选/全不选；底部操作条「移动」「删除」，
未选中时按钮禁用并提示「请选择要处理的笔记」。多选时长按也是切换选中（不弹菜单）。
批量移动的目标可以是别的笔记库，也可以是「移出笔记库（回到我的轻笔记）」。

笔记列表项（`NoteListTile`，笔记库页与详情页共用）显示：置顶图钉（有则显示）、标题（1 行）、
相对时间、正文前 200 字纯文本（无则不显示这一段）。多选模式下左侧是勾选图标、
整行加一层淡底色，让"已选中"一眼看得出来。

### 3.5 笔记库详情页

- 库内笔记列表；空库显示「该笔记库暂无笔记」+「点右下角 + 在这里新建一篇。」；
- 右下 FAB：在此笔记库新建笔记；
- 顶栏搜索是**库内搜索**（不含「我的轻笔记」——进到库里再搜，预期就是"在这个库里找"）；
- 顶栏「更多」：多选笔记 / 重命名笔记库 / 删除笔记库。
  **刻意没有「新建子笔记库」**——笔记库是平铺的，不能嵌套；
- 删除笔记库后自动退回上一层（笔记库页）。

### 3.6 笔记编辑页：编辑 / 阅读两态

| 形态 | 内容 | 右上角 |
|---|---|---|
| 编辑 | 标题输入框 + 正文输入框 + 底部格式工具栏 | **一个勾**：点了保存并进阅读态 |
| 阅读 | Markdown 渲染后的只读视图（按片渲染） | 「编辑」文字按钮 + **三个点**菜单 |

- 从列表/搜索结果进来默认进**阅读**（`startInReading: true`）；从"新建"进来是编辑；
- 两态共用同一个 `TextEditingController`，切换不丢草稿；
- 顶栏标题位置显示**保存状态**：未保存 / 保存中… / 已保存 / 保存失败（失败用错误色）；
- 编辑态**不放菜单**：菜单里是删除/移动这类"对已存内容"的操作，
  而此刻屏幕上还有没保存的改动——先保存、进阅读态、再动菜单，顺序上不会出现"删了却发现刚才的改动没存"。

**保存方式：手动。保存只发生在两个地方**——右上角那个勾，以及退出询问里选「保存并退出」。
正文变了只是把状态标成"未保存"，不排任何后台写盘。切片（搜索用的分段）也就在保存那一下更新。

**退出时若有未保存改动会问一句**（`PopScope(canPop: false)`），三个选项：

| 选项 | 结果 |
|---|---|
| 取消 / 点外面 | **留在编辑页**（退出被拦下） |
| 放弃改动 | 直接退出，改动不落盘 |
| 保存并退出 | 先保存再退出；**保存失败（超硬上限）就不退出**，否则用户以为存了其实丢了 |

没有未保存改动时直接放行，不打扰。

**篇幅上限（正文按 UTF-8 字节数分三档，只在软上限以上才出现横幅）**：

| 档位 | 阈值 | 用户看到 |
|---|---|---|
| 轻提示 | ≥ 80 KB | 「笔记较长（x KB）」+「继续变长可能影响编辑流畅度。」（中性色） |
| 强警告 | ≥ 90 KB | 「笔记偏长（x KB）」+「建议拆成多篇。还能继续编辑，超过 100 KB 就无法保存了。」 |
| 硬上限 | ≥ 100 KB | 「超出上限（x KB），无法保存」+ **「裁剪」按钮** |

上限是**拒绝保存**而不是阻止继续输入——拦输入要处理输入法组字、粘贴、撤销，漏一处就丢字。
点「裁剪」会先弹确认：「裁剪到 80 KB？」/「会删掉末尾约 x KB 的内容。**这个操作不能撤销**。」
裁剪不可恢复，所以只有硬上限这一档才给这个按钮（软/强档不给，避免误触）。
空草稿（标题与正文都空白）**不会被写进库**，连笔记都不创建。

**格式工具栏 6 个按钮**：加粗 / 斜体 / 下划线 / 列表 / 待办 / 标题。
前三个包裹选中文本（没有选中就插入占位词并选中），后三个在行首加/去前缀（再点一次即取消）。

**图片：不支持插图。** 正文里出现 `![alt](https://…)` 时**不加载图片**，只把 alt 与 URL
当文本显示（URL 可选中复制）。理由是渲染即向第三方服务器发请求（隐私）、图床挂了就是破图且
用户收不到提示、小红书/微信一类链接带防盗链根本加载不出来——不渲染 = 不发任何请求。

**阅读视图按片渲染**：正文切成一片片 Markdown widget，每片套一个 key。
从搜索结果点「笔记内容」进来时，会滚动到命中那一片（`Scrollable.ensureVisible`，
略靠上 6% 以免看起来像文章开头），并给那一片一层淡底色——
只滚动不标记的话，用户滚到那儿也看不出到底是哪一段被搜到了。
正文为空时显示「_（正文为空）_」。字号由「设置 → 外观 → 字体大小」统一控制。

阅读态的三个点菜单：

| 项 | 前提 / 行为 |
|---|---|
| 删除笔记 | 确认框「删除笔记」/「「标题」将被删除。」→ 取消 / 删除；删除后自动退出该页 |
| 复制全文 | 复制**纯文本**（标题 + 正文）到剪贴板，提示「已复制全文」 |
| 加入笔记库 / 移动到笔记库 | 未归档的显示前者，已归档的显示后者；打开笔记库选择器（可「移出笔记库」，也可就地新建笔记库） |

笔记还没创建（新草稿、还没落盘）时点菜单动作，会先落盘；实在没内容就提示「先写点内容，再操作这条笔记」。

### 3.7 搜索页

- 进页面**自动聚焦**输入框（打开搜索就是为了打字）；
- 输入 250ms 防抖后才查询（中文输入法组字会连续触发 `onChanged`）；
- 关键词在标题与摘要里**高亮**；关键词长度 ≥ 2 才记进搜索历史（去重、超量截断）；
- 未输入时显示「搜索历史」chips，点一条即用它重搜；右上「清空」有确认框
  （「清空搜索历史」/「将删除全部搜索历史记录。」）；没有历史时提示「输入关键词搜索标题和正文」；
- 有结果时先一行「找到 N 条结果」，再分两节展示：

| 分类 | 含义 | 点进去 |
|---|---|---|
| **笔记（N）** | 标题命中，整篇相关 | 阅读态，从头看 |
| **笔记内容（N）** | 正文某一片命中 | 阅读态，**滚动定位到命中那一片并高亮**；列表项额外显示所属小节与命中片段 |

两类都进**阅读**视图（用户是来找内容的，不是来改的）。
无结果时显示「没有找到相关笔记」并说明「当前是关键词匹配，不是语义搜索」。

搜索范围：笔记库页进来是**全局**（含「我的轻笔记」）；笔记库详情页进来只搜本库（不含轻笔记）。

**结果怎么排序、最多几条**：标题命中 3 分、正文片命中 2 分，**同一片里命中多次继续累加**，按分数降序；
默认最多 **20 条**。同分按标题稳定排序，所以同一个库、同一个词，两次搜到的顺序一样。
「笔记内容」的列表项在标题下面多两行信息：所属小节（`heading`，形如「项目A / 风险」；
**没有小节就不显示这一行**）与命中片段（命中位置**前后各 40 字**，换行压成空格）；标题为空的那条显示「无标题」。

能搜到中文 2 字词（记忆 / 间隔 / 习惯）是因为匹配用的是 `LIKE '%词%'`，不是分词索引；
`%` 与 `_` 按字面搜；软删的笔记不出现在结果里，限定笔记库时库外的一条也不返回。

### 3.8 AI 助手页

顶栏：会话记录（底部弹层，可删除单条会话）、新建会话。

**没有授权确认闸门**（设计定案）：插上 Key 就能直接发指令。
曾经有过一条"首次进入的隐私横幅"（点「我已了解，开始使用」才允许发送），
**整体已移除** —— 不把隐私做成一个需要用户操作的功能。
"会发什么给 DeepSeek"这件事仍在设置 → AI 里以**说明文字**告知（告知，不是需要同意）。

输入区（自上而下依次是）：

| 元素 | 交互 |
|---|---|
| 工作区 | 点开**三态面板**（`lib/features/ai/ui/workspace_sheet.dart`）：不选择 / 全体空间 / 选择笔记库。选「选择笔记库」时展开复选清单，可多选，并可单独勾「我的轻笔记」；「确定」才生效 |
| 思考强度 | 底部弹层三档：低（最快最省）/ 中（默认）/ 高（最慢最贵，适合复杂结构化整理）；「中」以上才真正开思考模式 |
| `+` 附件 | 「选择文件」（勾选要发送的笔记，确认后才生效，只发送勾选的那些）/「选择笔记库」（等价于改工作区） |
| 输入框 + 发送 | 发送时若已选笔记，输入框上方常驻提示条「本次将发送 N 篇笔记的内容」+「清空」 |

工作区决定 AI 能看到哪些笔记，**同时是工具的范围**（搜索、列笔记都被它限制）；
显示名是现查的（笔记库删了就不会在标签里留一个 uuid），默认「未选择」。

**AI 写操作必须用户点头**（`lib/features/ai/ui/agent_dialogs.dart`）：

- 确认弹层显示"改什么"，而不是"AI 想改这条笔记"：标题 + 摘要，
  能给出前后文时并排显示**「改前」/「改后」**两个文本块（超过 600 字截断并标注）；
- 删除这类危险操作把按钮改成**红色「删除」**，普通改动用「允许」，两者都可「取消」；
- **点弹层外面不算同意**（`barrierDismissible: false`），必须明确选；
- 手快点两下只执行一次；
- 改完之后底部弹一条可撤销提示：「已修改《标题》」+「撤销」，点撤销即回滚上一次修改
  （标题为空时显示「已修改《无标题》」；点了之后要么提示「已撤销」，要么提示「没有可撤销的修改」）；
- **删除类操作没有撤销**：没有回收站，撤销栈里也没有删除这一项——唯一的防线是确认框那几句话，
  删除确认的摘要就是「删除《标题》。**删了就找不回来**（没有回收站）。」
  （代码里那对 `**` 同样是字面量，弹层不是 Markdown，界面上会原样显示）。

**「AI 在等你回答」是常驻提示条**：AI 用 `askUser` 提了问题就落库（挂起是持久化的），
所以杀掉 App 重开也照样能看到这条提示、点一下就接着答。
答题层支持输入文本 / 单选 / 多选 / 确认（好 / 不用），**永远可以取消**——
"拒绝"是合法回答，也是用户从挂起状态脱身的唯一出口。没有可选项时不会显示空列表，
而是提示"可以取消，然后用一句话告诉我该怎么做"。
两个细节：答题层是**必须明确作答或取消**的那种（代码里的 `isDismissible: false`，注释写着"随手一划不算"）；
非确认型的「确定」在选够之前是灰的（文本不能为空，单选要选满一项，多选至少一项），
输入框提示词是「输入你的回答…」。

### 3.9 设置：首页只做导航

设置首页每一项都是「图标 + 名称 + **当前值** + 箭头」，点进去才改；
从子页返回时首页自动刷新摘要。

```
设置
├── 个性化
│   ├── 外观        当前主题（跟随系统 / 浅色 / 深色）
│   └── 编辑器      手动保存（无可改项，只作说明）
├── AI              已配置 Key · <模型> / 尚未配置 API Key；未配 Key 时图标为错误色
├── 数据
│   └── 存储与备份  当前目录（或「临时位置（有风险）」+ 错误色）
└── 其他
    ├── 用量与成本  查看累计 AI 花费
    └── 关于        版本、技术栈、隐私说明
```

**为什么这么改**：破坏性操作（换工作目录、导入备份包）和日常开关（主题、字号）混在一页时
很容易误触。点进去才改，等于多了一道"我是来做这件事的"确认。

各子页要点：

| 子页 | 内容 |
|---|---|
| 外观 | 主题三选；正文字号滑块 0.8–1.4（6 档）+ 示例文字实时预览。**只影响笔记正文的编辑与阅读视图**，不影响界面其他文字 |
| 编辑器 | 只说明「手动保存」：编辑时右上角是一个勾，点它保存并进入阅读态；退出时有未保存改动会先问。**「自动保存」开关已移除**——保存方式定案为手动，留个开关只会让人以为还能自动保存 |
| AI | API Key（不明文回填，只显示状态；保存 / 测试连接 / 删除，删除有确认；Key 只在系统钥匙串，不进备份包）。模型固定 `deepseek-flash`；思考强度在 **AI 页顶部按会话选**，不在这里 |
| 存储与备份 | 数据库位置卡片（真实路径 + 状态 + 说明）、更换工作目录、诊断（把各候选路径与错误列出来）、导出备份包（.zip）、从备份包导入、清空 AI 历史；「恢复默认存储位置」只在当前不是私有目录时出现 |
| 用量与成本 | 累计估算成本 + 统计范围说明（清空 AI 历史会归零） |
| 关于 | 版本、技术栈、数据与隐私说明 |

**这一页集中了所有会碰数据文件、且不可逆或需要重启的操作**，各自的反馈：

| 操作 | 用户看到什么 |
|---|---|
| 导出备份包 | 桌面：系统保存对话框选位置。**Android 没有保存对话框**（`file_selector` 未实现 `getSaveLocation`），改成写进 App 缓存后拉**系统分享面板**让用户在「保存到文件 / 发微信 / 发网盘」里选去处。**取消 = 不导出**（不再兜底写私有目录）。完成后弹「备份已导出」或「备份包已生成」：路径（Android 上是「去分享面板选去处」）、大小、内容统计，并说明包里是标准 SQLite、**不含 API Key** |
| 从备份包导入 | 先校验，包不合法就弹「这个备份包不能用」+ 原因。合法则弹确认：备份时间、来源平台、内容摘要，并选**覆盖当前数据**或**保留为另一个文件**；明确说明导入前的旧库会改名 `before-import-….sqlite` 留在同目录。点「导入并重启」→ 因为数据库已打开无法原地替换，会再问一次「立即重启 / 稍后手动重启」 |
| 更换工作目录 | 目标目录里已有数据库时**绝不覆盖**，而是问：「使用它」（直接用那里的旧笔记，当前数据不带过去但留在原处）/「换个目录」/ 取消。正常切换会把数据一致性快照复制过去，然后询问重启 |
| 恢复默认存储位置 | 搬回 App 私有目录，同样询问重启 |

## 5. 提示（LogBar）的使用规范

全 App **只有 `lib/core/widgets/log_bar.dart` 一个地方直接操作 SnackBar**，业务代码一律调它。
不是洁癖，是因为 Flutter 的 SnackBar 有两个坑：

1. **带按钮的提示永不消失**：`persist = persist ?? action != null`，而超时定时器遇到
   `persist == true` 直接 return。所以只要传了 `SnackBarAction`，`duration` 就被完全忽略。
   LogBar 统一显式指定 `persist`。
2. **SnackBar 是排队的**：前一条没走完，后一条一直等。所以 LogBar 在任务进行中（有 `busy`）时
   会**丢弃**普通提示——否则 AI 生成那几秒里用户点的几下，会在任务结束后变成一串过期提示刷屏。

| 级别 | 什么时候用 | 自动消失 |
|---|---|---|
| `info` | 中性反馈：确认、引导（没有成功/失败倾向） | 3 秒 |
| `success` | 操作**做成了** | 3 秒 |
| `warn` | 做完了但**结果不合预期**（结果为空、被规则拦下） | 4 秒 |
| `error` | **失败**，或挡住了用户想做的事 | 3 秒；**能穿过 busy 被看到** |
| `action` | 带按钮（如撤销），或内容必须被看清（如备份留档路径） | **默认常驻**，要自动走就显式传 `persist: false` |
| `busy` | 耗时任务进行中（带转圈，由返回的句柄收起） | 由句柄；兜底 5 分钟 |

- 怎么选：用户想做的事被挡住了 → `error`；做完了但结果不合预期 → `warn`；做成了 → `success`；
  纯粹告知 → `info`。`error` / `warn` 会带图标，扫一眼就能分辨"出问题了"还是"只是提示"。
- `busy` **必须**用 `try / finally` 包，否则某条 `return` 越过了 `close()` 就会让转圈提示一直挡着。
- **撤销没有时限，也不该有时限**：Flutter 的行为是"传了 `SnackBarAction` 就彻底忽略 `duration`"（见上），
  所以"5 秒内可撤销"**做不到**。定案就是 `action` 常驻 + 用户点「撤销」，撤销栈也只留最近几次
  （撤销是"手滑了救一下"，不是版本历史）。
- 需要**先 pop 掉弹窗再提示**时用 `LogBar.successTo(messenger, ...)`：pop 之后原 context 已失效，
  要在 pop 之前取好 messenger。
- 行为由 `test/log_bar_test.dart` 的 11 条用例锁住。

## 7. 关键行为约定

这几条容易在重构时被改坏，写下来：

| 行为 | 说明 |
|---|---|
| **删除笔记库不删笔记** | 库内笔记 `notebookId → null`、`isInbox → true`（回到「我的轻笔记」）。直接级联删笔记是数据丢失事故 |
| **未归档笔记必须可见** | `isInbox = false && notebookId IS NULL` 这种组合在两个入口都看不到，等于丢失。创建未归档笔记时写 `isInbox = true`，迁移里还修正过存量数据 |
| **笔记库是平铺的** | 没有层级、没有父子级联、界面上不提供"新建子笔记库" |
| **示例数据在启动时写** | 不能挂在某个页面上——轻笔记页要抽卡片，首屏就需要笔记库已存在（曾经挂在 AI 页，导致首屏看起来是空的） |
| **AI 不能直接改数据** | AI 给出的写操作先弹确认层（改前/改后），用户点了「允许」才执行；删除用红色「删除」 |
| **只发勾选的笔记** | 每次 AI 请求只带用户在 `+` 里显式勾选的笔记；未勾选时只发指令本身 |
| **卡片流不自动调 AI** | 翻卡片不烧 token。素材摘要由生成卡片时顺带产出（`ai_note_summaries`，翻卡本身不发请求） |
| **追加只由下拉触发** | 首次进入**替换**（3 张）、下拉**前向追加**（新的插到最前面，累积成 6、9…）。滚动不做任何事——曾经加过"滚到底自动加载"，而窗口重新布局（比如切后台回来）也会产生滚动通知，被误当成"用户滚到底"，卡片自己就往后长 |
| **每次看到的内容不重样** | 素材 = 摘要 + **片内 400 字窗口**；窗口位置轮换（`next_window_start`）、用过的片 `last_used_at` 落库（最久没用过的优先）、同一篇笔记在最近 12 张里最多出现 1 次 |
| **收下状态从库里推导** | 不记在页面内存里：卡片按"标题 + 正文"指纹（或本次会话记下的 noteId）实时对「我的轻笔记」；用户别处删了/改了，卡片跟着变 |
| **卡片/详情页只能收下，不能归档** | 收下的落点是「我的轻笔记」。收进指定笔记库要走笔记库页或编辑页（见 §9.5） |
| **空草稿不入库** | 新建笔记走"延迟创建"：标题与正文都空白就返回，库里不会留下空白笔记 |
| **手动保存 + 退出询问** | 只有勾与「保存并退出」两处写盘；退出时有未保存改动必须问，保存失败不许退出 |
| **笔记篇幅上限** | 正文 80 KB 轻提示 / 90 KB 强警告 / 100 KB 拒绝保存（可裁剪）；标题保存前截断到 200 字 |
| **换库必须重启** | 导入备份、换工作目录都要重启才生效，因为数据库已打开时无法安全替换文件 |
| **破坏性操作先留档** | 导入前旧库改名留档（`before-import-….sqlite`）；导出**只**出用户要的那一份，不在私有目录另留 |

## 9. 明确不做（刻意没有的功能）

§8 记的是"旧文档哪些说法已经过时"，本节记的是"**哪些功能是刻意没有的**"。
这类东西不写下来，下一轮很容易被当成漏做而补上——而它们当初都是有理由被拿掉的。
（最后一小节 §9.5 相反：那是"还没打通"，不是"不做"。）

### 9.1 卡片流

| 没做 | 为什么 |
|---|---|
| **卡片持久化** | 生成结果只在内存，收下才落库。卡片是"随手刷到的东西"，不是收藏品。（唯一例外：每篇笔记的 AI 摘要与跨启动预留） |
| **卡片上的摘要 / 预览** | 两种做法都试过：截正文前 N 字读起来像被截断；让 AI 单独生成摘要要维护两个内容字段，而且**模型不守字数**（要求 45–60 字，稳定返回 116–160 字）。定案是只有标题 |
| **收藏 / 不感兴趣 / 到期复习** | 那是上一版"复习已有笔记"的配套（`note_feed_state` 的到期时间、间隔天数、难度因子、收藏），卡片改成 AI 新生成之后就没有意义了；配套的记忆卡片功能后来也整体移除 |
| **收下前编辑内容** | 卡片是只读预览，内容此刻还没落库。要编辑就先收下——收下后它就是一条普通笔记 |
| **卡片上的左右滑手势** | 左滑删除只属于**笔记列表项**；卡片内容还没落库，没有可删的对象 |
| **收下时选笔记库 / 从卡片或详情页新建笔记** | 收下的落点固定是「我的轻笔记」（见 §3.2、§9.5） |
| ~~跨启动缓存卡片~~ | **这个已经做了**（§3.1 的跨启动预留），所以它不在"不做"里 |

### 9.2 搜索

| 没做 | 为什么 |
|---|---|
| **FTS5 / bigram 分词索引** | 在项目自带的 SQLite 上实测：`unicode61` 把整段中文当成一个 token（2/3/4 字查询都是 0 条）；`trigram` 要求查询 ≥3 字符，中文最常见的 2 字词必然 0 条。`LIKE '%词%'` 各种长度都命中，先用它 |
| **拼音搜索** | FTS5 没有拼音分词器，要额外存一列转写 + 一份词典 |
| **RAG / embedding（语义搜索）** | 产品明确否决："这个一点都不轻量化"。搜索页的空结果里也直说"当前是关键词匹配，不是语义搜索" |
| **AI 查询改写（扩词）** | 列为后续可选项，本次不做 |

### 9.3 AI 与数据安全

| 没做 | 为什么 |
|---|---|
| **回收站 / 恢复入口** | 产品决定不做。删除的内部实现仍是软删除（`deletedAt`，数据还在库里），但**没有恢复入口**——所以删除类操作**没有撤销**，确认框是唯一防线 |
| **让 AI 碰敏感数据** | 19 个工具里根本没有"改设置 / 改 API Key / 执行 SQL / 文件系统 / 清空数据库"的入口，这是**结构性保证**；写操作还一律先过 App 的确认层，模型绕不过去 |
| **批量超过 10 条 / 删除全部** | 灾难性操作 |
| **笔记的版本号列** | 用"全文快照比对 + 锚点校验"就够了，不为此引入版本列 |
| **每篇笔记的用户可见摘要** | 展示型摘要随 v7 删除；现在的 AI 摘要（`ai_note_summaries`）是卡片流的素材，**用户看不到** |
| **会话切片落库** | 现算毫秒级；落库会让表跟着对话无限增长 |
| **历史全量重发** | 只带最近 5 轮、单条截断 500 字——历史是每条消息都重发的，不设上限成本是 O(N²) |

### 9.5 已知差距：归档那一步是断的

**不是"不做"，是还没打通，所以别把它当成已经有的能力。**

「轻笔记」这条链目前是：卡片生成 → 点开看全文（详情页，只读）→ 「加入我的轻笔记」。
**到"归进某个笔记库"就断了**：

| 能做到 | 做不到 |
|---|---|
| 卡片上「加入我的轻笔记 / 从我的轻笔记移出」 | 卡片或详情页上**选一个笔记库**直接归档 |
| 详情页看 AI 写的全文、收进「我的轻笔记」 | 卡片或详情页里**新建笔记**、编辑、删除 |
| 收下后到笔记库页 / 编辑页再走一步归档 | 一步到底（"生成 → 归档到某库"） |

要归档，用户得离开卡片流，去笔记库页长按那一条（移动到笔记库）或进阅读态菜单；
也就是说功能描述里的"轻笔记长出笔记"只覆盖到**收进「我的轻笔记」**这一半。
以后要么补上"收下时就近选库"，要么就把这句话改准——不要以为归档已经打通。
