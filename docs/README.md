## 怎么加一个新功能

**没有单独的规格书目录了**（曾经有过 `docs/specs/`）。

现在的做法：**改动直接写进对应的设计文档** —— 界面改动写进 [界面设计](界面设计.md)，
表改动写进 [数据库设计](数据库设计.md)，AI 行为改动写进 [AI接入设计](AI接入设计.md)，依此类推；
完整步骤见 [架构和功能开发流程设计](架构和功能开发流程设计.md) 第八节。

## 两条维护约定

**1. 文档与代码不一致时，以代码为准，然后改文档。**

不是"文档写了就算数"——代码是唯一运行的真相。发现不一致应当作 bug 修，
而不是当"文档过时了无所谓"。

**2. 改表必须同时改 `tables.dart` 与 [数据库设计](数据库设计.md)。**

`tables.dart` 文件头已经写了这条提醒。数据模型文档脱节的代价很高
（错的字段名会让人写出跑不通的代码），所以这条单独强调。

各份文档末尾大多带一节「**原文档里已过时、本次已修正的说法**」—— 那是文档重构留下的
修订痕迹，用来核对"哪些旧结论已经不成立"，读到时不必当成正文。
