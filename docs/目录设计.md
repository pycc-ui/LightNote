# 目录设计

本文只讲一件事：**代码目录结构与命名规范**。
读完应当能直接回答两个问题：*这个新文件放哪*、*它该叫什么名字*。

> [界面设计](界面设计.md)（`ui/` 里的页面清单）、
> [数据库设计](数据库设计.md)（`core/db/tables.dart` 里的表）。

本文按**实际列出的目录与文件**写成，不是照抄旧文档。

## 2. 顶层四个目录

| 目录      | 放什么                               | 不放什么                    |
| ------- | --------------------------------- | ----------------------- |
| `lib/`  | 全部生产代码，唯一会进 App 包的东西              | 测试、脚本、文档、任何实验代码         |
| `test/` | 自动化测试，扁平一层                        | 测试辅助数据的大二进制、生产代码        |
| `tool/` | 开发辅助脚本：一个 `inspect_db.dart`（直接查库） | 会被 App import 的 Dart 代码 |
| `docs/` | 所有设计文档 + 索引                       | 代码、截图素材堆                |

---

## 3. lib/ 的四层

| 层           | 职责                                 | 判断标准                      |
| ----------- | ---------------------------------- | ------------------------- |
| `main.dart` | 进程入口：`runApp` 之前要做的事（装配依赖 + 启动前自检） | 只有启动相关代码能进来，**一个文件**，不再增长 |
| `app/`      | 启动期的应用外壳：导航骨架 + 启动期的一次性动作          | 换掉任何一个 feature，这里都不用改     |
| `core/`     | 与具体功能无关的基础设施                       | **删掉任何一个 feature，它依然要存在** |
| `features/` | 业务功能，一功能一目录                        | 删掉它，App 少一块能力             |

**最容易搞错的是 `core/` 与 `features/` 的边界**，用这一条判断：

> 这个文件**只服务于某一个功能**吗？
> 是 → `features/<那个功能>/`；否 → `core/`。

例：备份服务只被设置页调用，但它处理的是整库导出与恢复、不隶属任何单个功能，所以进 `core/backup/`。

## 4. core/ 逐目录说明

| 目录 / 文件         | 放什么                                                                                                                     | 不放什么                                           |
| --------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| `app_info.dart` | 产品名、版本、包名的**唯一来源**                                                                                                      | 会被产品改名影响的业务逻辑                                  |
| `backup/`       | 整库备份与恢复（打包、导入、选文件、重启、待导入状态）                                                                                             | 单表导出、单个 feature 的数据搬运                          |
| `db/`           | 数据库连接与表定义：`app_database.dart`（连接+查询）、`tables.dart`（Drift 表）、`models.dart`（非表结构 DTO）、`database_location.dart`（库放哪、切工作目录） | 业务查询（那些属于各 feature 的 `data/`）                  |
| `prefs/`        | 轻量偏好（`SharedPreferences` 一类）                                                                                            | 敏感数据（去 `secure/`）、结构化数据（去 `db/`）               |
| `secure/`       | 系统钥匙串读写（API Key 等）                                                                                                      | 普通偏好、缓存                                        |
| `seed/`         | 首次启动写入的示例数据                                                                                                             | 迁移逻辑、测试夹具                                      |
| `theme/`        | 主题与尺寸常量（`app_theme.dart`、`dimens.dart`）                                                                                 | 单个页面的私有样式                                      |
| `util/`         | **无状态纯函数**（`text_utils.dart`、`ai_limits.dart`）                                                                          | 任何持有状态、IO、Widget 的东西                           |
| `widgets/`      | 跨 feature 复用的通用组件（`log_bar.dart`、`markdown_view.dart`）                                                                 | 只被一个 feature 用的组件（放那个 feature 的 `ui/widgets/`） |

`core/` 的子目录名用**领域名**（`backup` `db` `prefs` `secure` `seed` `theme`），
不要用技术名（`helpers` `utils` `common` `misc`）。
`util/` 是唯一例外，只放无状态纯函数。

## 5. features/ 逐目录说明

一个 feature 才有一个目录，`features/` 下**没有**平铺的文件。

| 目录                     | 放什么                                                                                                          | 不放什么                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| `ai/`                  | DeepSeek 接入、Agent 循环与工具调用、AI 页                                                                               | 笔记本身的存储（那是 `note/`）              |
| `ai/data/`             | HTTP 客户端与配置：`deepseek_client.dart`、`deepseek_config.dart`                                                    | 提示词与业务规则（去 `domain/`）            |
| `ai/domain/`           | Agent 循环、工具定义与执行、问答解析、提示词、AI 侧仓储                                                                             | Widget、`showDialog`              |
| `ai/ui/`               | `ai_page.dart`（整屏）、`agent_dialogs.dart`（对话框集合）、`workspace_sheet.dart`（底部弹窗）                                  | 直连 Dio、直写 SQL                    |
| `note/`                | 笔记域：轻笔记卡片流、笔记库、编辑、搜索、切片                                                                                      | AI 供应商细节（那是 `ai/`）               |
| `note/data/`           | 5 个仓储 + 1 个搜索服务：所有读写库的动作                                                                                     | 纯算法（去 `domain/`）                 |
| `note/domain/`         | 值对象与纯算法：`note_chunk.dart`、`note_chunker.dart`、`history_chunker.dart`、`feed_window.dart`、`search_result.dart` | 任何 IO、任何 Widget                  |
| `note/ui/`             | 7 个页面                                                                                                        | 复用给小页面的组件（去 `ui/widgets/`）       |
| `note/ui/widgets/`     | 只在 note 内复用的组件与选择器                                                                                           | 跨 feature 的组件（去 `core/widgets/`） |
| `settings/`            | 设置域，**只有 UI**（数据都靠别的 feature 的仓储）                                                                            | 自己造一套数据访问层                       |
| `settings/ui/`         | `settings_page.dart`（首页，只做导航）                                                                                | 各子页的具体内容                         |
| `settings/ui/pages/`   | 各子页（关于、AI、外观、编辑器、存储、用量）                                                                                      | 共用骨架                             |
| `settings/ui/widgets/` | 子页共用的骨架（`settings_scaffold.dart`）                                                                            | 单个子页的私有组件（就近放页面旁）                |

### `data` / `domain` / `ui` 怎么分

| 目录        | 放什么               | 真实例子                                          |
| --------- | ----------------- | --------------------------------------------- |
| `data/`   | 与外部打交道：数据库、网络、文件  | `note_repository.dart`、`deepseek_client.dart` |
| `domain/` | 业务规则，不碰 IO 也不碰 UI | `note_chunker.dart`（纯切分）、`prompts.dart`       |
| `ui/`     | 页面与组件             | `inbox_page.dart`                             |

**不是每个 feature 都要三层。** 只有 UI 的功能只建 `ui/`（`settings/` 就是这样）。
空目录不要建——`flutter analyze` 不报，但只会让人困惑。

**已知的历史例外**：`ai/domain/` 下的 `ai_repository.dart`、`ai_chat_repository.dart` 是仓储，
按本文规则应在 `ai/data/`（`note/` 就是这么分的）。它们先于规则存在，本次**不改名不搬家**；
但新写的仓储一律进 `data/`。

## 6. test/ 、tool/ 、docs/

### test/

- **保持扁平**，不建子目录；文件名 = `<被测对象>_test.dart`，与被测文件同名。
- Widget 测试在文件名里点明：`empty_note_widget_test.dart`、`log_bar_test.dart`。
- 曾有一类 `<对象>_live_test.dart`（需要真实网络与 API Key 的集成测试，文件首行打
  `@Tags(['live'])`、`dart_test.yaml` 里默认跳过）。那 3 份已按用户定案删除，
  命名约定与标签配置也一并取消——原因、代价与"将来要加回来怎么做"见
  [测试设计](测试设计.md) 第四节。

### tool/

- 这里只放**开发辅助的 Dart 程序**：目前是 `inspect_db.dart`（直接查数据库内容）。
  它要 import 工程自己的依赖，所以留在工程里。
- **App 实际使用的图标**在 `windows/runner/resources/` 与
  `android/app/src/main/res/mipmap-*/`，那是产物、必须保留。
- `legacy/` 只放已不用的历史脚本，**只存档不维护**；新脚本不要放进去。

### docs/

- 全部文档都在 `docs/`，文件名**不带数字前缀**，直接命名（`<主题>设计.md`）。
- 一个文档只记录一个事情；文档之间互相独立，不靠阅读顺序。
- 改动**直接写进对应的设计文档**（曾经有 `docs/specs/` 放单功能规格书，已撤销）。功能下线后在对应文档里标「已废弃」，不删。
- 现存 `01-` 到 `04-` 四个带编号的文档是旧规则的遗留，已删除（本次重构）；**不要模仿**。

## 7. 命名规范

### 一句话规则

> 文件名 = 小写 snake_case 的 `<领域名词>_<角色>.dart`，角色词必须来自下面的表；
> 目录名 = 小写单数领域名，不用下划线；类名 = `UpperCamelCase`，常量 = `k` 前缀的 `lowerCamelCase`。

拼不出角色后缀，通常说明这个文件的职责还没想清——先想清，再建文件。

### 目录命名

| 规则          | 说明                                             | 例子                                                            |
| ----------- | ---------------------------------------------- | ------------------------------------------------------------- |
| 全小写、单数      | 一个目录代表一个功能域或一类角色                               | `note` `backup` `ui`                                          |
| 不用下划线、不用连字符 | 多词就换个更短的名词                                     | `note_ai_asset_repository.dart` 在 `data/`，不建 `note_ai_asset/` |
| 平台生成目录除外    | `android/`、`mipmap-hdpi/`、`__pycache__/` 由工具产生 | 别手动改                                                          |

### 文件角色后缀表

按职责取词，**按功能分目录、按角色定文件名**。

| 后缀                     | 用于                   | 真实例子                                                                                     |
| ---------------------- | -------------------- | ---------------------------------------------------------------------------------------- |
| `_page`                | 整屏页面（自带 `Scaffold`）  | `inbox_page.dart`、`ai_page.dart`                                                         |
| `_sheet`               | 底部弹窗**内容**           | `workspace_sheet.dart`                                                                   |
| `_dialog` / `_dialogs` | 单个对话框内容 / 一个功能的一组对话框 | `agent_dialogs.dart`、`file_dialogs.dart`                                                 |

| `_repository`          | 单表/单实体的数据仓储          | `note_repository.dart`                                                                   |
| `_service`             | 跨功能服务，无 UI           | `backup_service.dart`、`search_service.dart`                                              |
| `_client`              | 外部接口客户端              | `deepseek_client.dart`                                                                   |

### 大小写与标识符

| 对象        | 规范                     | 真实例子                            |
| --------- | ---------------------- | ------------------------------- |
| 文件名 / 目录名 | `snake_case` 全小写       | `note_chunk_repository.dart`    |
| 类名 / 枚举名  | `UpperCamelCase`       | `NoteChunker`、`WorkspaceMode`   |
| 变量 / 方法   | `lowerCamelCase`       | `includeUnfiled`                |
| 顶层常量      | `k` + `UpperCamelCase` | `kAppDisplayName`、`kAppVersion` |
| 私有成员      | 前缀 `_`                 | `AppSpacing._()`                |
| 中文        | 只出现在注释、文档、界面文案         | 文件名里**绝不**出现中文（`docs/` 除外）      |

### 命名禁忌

| ❌ 别用                                                            | 原因              | ✅ 改成                                     |
| --------------------------------------------------------------- | --------------- | ---------------------------------------- |
| `helpers.dart` / `utils.dart`                                   | 什么都往里塞，最后成垃圾桶   | 按领域拆，或进 `core/util/`                     |
| `common.dart` / `misc.dart`                                     | 同上              | 同上                                       |
| `manager.dart` / `handler.dart`                                 | 没说清职责           | `_service` / `_repository` / `_executor` |
| `new_xxx.dart` / `xxx2.dart` / `xxx_v2.dart` / `xxx_final.dart` | 说明旧版没删干净        | 直接改旧文件                                   |
| `temp.dart` / `test1.dart`                                      | 临时文件会永远留下       | 建在正确的目录里                                 |
| 中文文件名                                                           | 打包、CI、跨平台都容易出问题 | 英文文件名                                    |

### 单复数

**feature 目录名用单数**（`note` `ai` `settings`），因为一个目录代表"一个功能域"。
**数据库表名用复数**（`notes`、`ai_calls`），因为一张表装多行。
两者不冲突，但别混。

## 9. 新文件放哪：决策树

```
要新加一个 .dart 文件（lib/ 下的生产代码）
│
├─ 它在 runApp() 之前就参与启动（装配依赖、启动自检、首屏前置动作）？
│   └─ lib/main.dart（入口本身）
│      或 lib/app/（启动期的外壳与一次性动作：导航骨架、示例数据引导、开发期 Key 文件）
│
├─ 它是应用级 UI 骨架（换掉任何 feature 都不用改的 UI）？
│   └─ lib/app/
│
├─ 它是某个功能的页面或组件？
│   ├─ 功能已存在
│   │   ├─ 整屏页面       → features/<功能>/ui/<名字>_page.dart
│   │   ├─ 子页（一组同类子页）→ features/<功能>/ui/pages/
│   │   └─ 组件/弹窗/选择器 → features/<功能>/ui/widgets/
│   └─ 是新功能 → 先按第 10 节建 features/<新功能>/，再重复上面三行
│
├─ 它是业务规则或算法，不读库、不发网络、不碰 UI？
│   └─ features/<功能>/domain/
│
├─ 它读库 / 发网络 / 写文件？
│   ├─ 只服务一个功能 → features/<功能>/data/
│   └─ 已被两个以上功能依赖，或与功能无关 → core/<领域>/（backup db prefs secure theme widgets）
│
├─ 它是无状态纯函数？
│   └─ core/util/
│
└─ 它跨 feature 复用的 UI 组件？
    └─ core/widgets/
```

**拿不准时的默认选择**：先放 `features/<功能>/` 下**离使用点最近**的地方
（就近放 `ui/widgets/`，而不是一步到位进 `core/widgets/`）。
等它真的被第二个功能复用了再往上提。**不要预先抽象**。

**说不出它属于哪个功能域**，那就是 `core/`。

## 10. 新增一个 feature 的步骤

1. 先在**对应的设计文档**里写清要做什么（界面改动写进 [界面设计](界面设计.md)，表改动写进 [数据库设计](数据库设计.md)，等等）。不再有单独的规格书目录。
2. 建目录：`lib/features/<名字>/`，按需建 `data/` `domain/` `ui/`（不用的别建）。
3. 写文件，文件名按第 7 节的角色后缀表。
4. 需要访问已有数据时**通过现有 repository**，不要新建直连数据库的类。
5. `flutter analyze` 零问题 + `flutter build windows` 通过。
6. 更新文档：[界面设计](界面设计.md) 的页面清单、[测试设计](测试设计.md) 的测试清单。

**判断该不该新建 feature**：

- 它有自己的数据表吗？有 → 新 feature。
- 它会出现在底部导航或设置首页吗？会 → 新 feature。
- 只是现有功能的一个新页面？→ **不新建**，放进现有 feature。
